**Paint.NET 3.36 behavior (transcribed from the source cited above).**

- *Glow* (`GlowEffect`). Properties **Radius** int 1…20 default 6, **Brightness** int −100…100 default 10, **Contrast** int −100…100 default 10 (labels "Radius", "Brightness", "Contrast"). Per render: `dst = GaussianBlur(src, Radius)`; `dst = BrightnessContrast(dst, Brightness, Contrast)` (in place, alpha untouched); then per pixel `dst = Screen(lhs: src, rhs: dst)` with the full `UserBlendOps` alpha composition — the original is the bottom layer, the blurred-and-adjusted copy is screened over it.
- *Soften Portrait* (`SoftenPortraitEffect`). Properties **Softness** int 0…10 default 5, **Lighting** int −20…20 default 0, **Warmth** int 0…20 default 10. Per render: `dst = GaussianBlur(src, 3·Softness)` (Softness 0 → radius 0 → copy); `dst = BrightnessContrast(dst, brightness: Lighting, contrast: −Lighting / 2)` (C# `int` division truncates toward zero: Lighting 3 → −1, −3 → 1, 20 → −10); `redAdjust = 1.0f + Warmth / 100.0f`, `blueAdjust = 1.0f − Warmth / 100.0f` (**`float`**); per pixel: `g = Desaturate(src)` = `(I, I, I, A)` with `I = GetIntensityByte(src)`; `g.R = ClampToByte((int)((float)I · redAdjust))`, `g.B = ClampToByte((int)((float)I · blueAdjust))` (float multiply, truncation toward zero); `dst = Overlay(lhs: g, rhs: dst)`.
- *Red Eye Removal* (`RedEyeRemoveEffect` + `UnaryPixelOps.RedEyeRemove`). Properties **Tolerance** int 0…100 default 70, **Saturation** int 0…100 default 90 (label "Saturation percentage"; its Description is the hint "Hint: For best results, first use the selection tools to select each eye"). No selection is required (the hint only advises one; the effect runs over the selection or, without one, the whole layer). Per pixel with straight bytes:
  ```
  difference = R − max(B, G)
  saturation = (int)(s · 255),  s = (max == 0 || delta == 0) ? 0 : delta / max   // HSV saturation in double: r = R/255.0, … ; max/min/delta of r, g, b
  if difference > Tolerance && saturation > 100 {
      i  = 255.0 · ((0.114·B + 0.587·G + 0.299·R) / 255.0)                      // GetIntensity, double, evaluated left to right
      R' = (byte)(i · (Saturation / 100.0))                                      // truncation
      out = (R', G, B, A)
  } else { out = (R, G, B, A) }
  ```
  Only the red channel changes; alpha is copied; color under alpha 0 is processed like any other.

**Fidelity decision applied in this spec (*Open questions* 1, 3).** Glow and Soften Portrait are compositions, and they are built from the **existing PaintDotMac definitions** of their parts instead of new 3.36 ports: the blur stage is exactly 0041's `GaussianBlur` (tent weights, clamp-to-edge, correct alpha, rounded to bytes), the adjustment stage is exactly 0031's integer Brightness / Contrast formula on those bytes, and the blend stage is exactly 0026/0027's Overlay/Screen channel function with the normative composition. So Glow on a layer equals, byte for byte, what a user gets by blurring a copy, adjusting it and screening it (up to the blur's ±1). The warmth tint keeps 3.36's `Float` semantics exactly (including its rounding quirks, e.g. Warmth 5 turns gray 100's red into 104, not 105). Red Eye Removal uses an **exact integer** form of 3.36's double math (*Scope* item 3), which equals 3.36 everywhere except a few input triples where 3.36's double rounding lands 1 below the exact value.

## User story

As a photo editor, I open **Effects ▸ Photo ▸ Glow…**, see **Radius 6, Brightness 10, Contrast 10**, and watch the highlights bloom live; **OK** adds one "Glow" step and **⌘F** ("Repeat Glow") glows again. I open **Effects ▸ Photo ▸ Soften Portrait…** (**Softness 5, Lighting 0, Warmth 10**) and get a soft, warm diffusion; lowering Warmth cools it. I select each eye with the Ellipse Select tool, open **Effects ▸ Photo ▸ Red Eye Removal…** (**Tolerance 70, Saturation percentage 90**, with the hint "Hint: For best results, first use the selection tools to select each eye" under the sliders), and the red pupils turn dark while everything outside the selection stays untouched.

## Scope & changes

Cross-cutting rules (unchanged from 0031/0041/0042): one file per effect conforming to `ImageEffect` with a schema, registered in `EffectRegistry.standard`; no hand-written effect dialog (AGENTS rule 5); every pixel change goes through 0031's `EffectSessionController` → `UndoBridge` (preview via `updateLiveState`, step via `commit`); straight 8-bit sRGB storage (rule 4; premultiplication only inside 0041's blur kernels); rendering off the main actor in 0031's runner (rule 7); selection clipping and antialiased edges by 0031's `EffectMaskBlend` (rule 8, FX-D); `Core` imports no AppKit/SwiftUI (D-19). `EffectRunner`, `CoreImageBridge`, `EffectRenderContext`, `EffectTileRenderer`, `EffectSessionController` are **unchanged**. Framework additions: two `static` composition helpers extracted from existing effects (items 4, 5; no behavior change) and the optional `hint` schema field (item 6).

   - No shortcut (Paint.NET has none; PRD §5.12 lists none); history icon default `.effect`; menu title "Glow…"; history step "Glow".
   - **Definition** (the oracle implements exactly this; the GPU matches within ±1 of it, *Test plan* explains the blur-tie rule). For every pixel with straight source `S`:
     1. `Bl = GaussianBlur(S, radius)` — 0041's definition, bytes (`A_out`, `C_out` rounded to nearest).
     2. `Adj = BrightnessContrast(Bl, brightness, contrast)` — 0031 item 9's integer formula on `Bl`'s bytes; `Adj.a = Bl.a`.

2. **`PaintDotMac/Core/Effects/Effects/Photo/SoftenPortrait.swift`** (new).
   ```swift
   public struct SoftenPortrait: ImageEffect {
       public init()
       public let id = "softenPortrait"
       public let name = "Soften Portrait"
       public let category = EffectCategory.photo
       public var parameters: [EffectParameter] {
           [.init(id: "softness", label: "Softness", kind: .integer(range: 0...10,   defaultValue: 5)),
            .init(id: "lighting", label: "Lighting", kind: .integer(range: -20...20, defaultValue: 0)),
            .init(id: "warmth",   label: "Warmth",   kind: .integer(range: 0...20,   defaultValue: 10))]
       }
       public var alphaMode: EffectAlphaMode { .straight }
       public static func blurRadius(softness: Int) -> Int                  // 3 · softness
       public static func contrast(lighting: Int) -> Int                    // (−lighting) / 2, Swift `/` truncates toward zero like C#
       public static func warmthFactors(warmth: Int) -> (red: Float, blue: Float)   // (Float(1) + Float(warmth) / Float(100), Float(1) − Float(warmth) / Float(100)), computed on the CPU in Float
       public static func tintedGray(_ c: ColorRGBA8, red: Float, blue: Float) -> ColorRGBA8   // (min(255, Int(Float(I) * red)), I, min(255, Int(Float(I) * blue)), c.a), I = (7471·B + 38470·G + 19595·R) >> 16
       public func inputPadding(for values: EffectParameterValues) -> Int   // = blurRadius(softness:)
       public func makeOutput(input: CIImage, values: EffectParameterValues, context: EffectRenderContext) throws -> CIImage
   }
   ```
   - No shortcut; icon `.effect`; menu title "Soften Portrait…"; step "Soften Portrait".
   - **Definition**: `Bl = GaussianBlur(S, 3·softness)` (softness 0 → `S` exactly); `Adj = BrightnessContrast(Bl, brightness: lighting, contrast: contrast(lighting:))`; `G = tintedGray(S, warmthFactors(warmth))`; `out = compose(dst: G, src: Adj, Channel.overlay)` (`Adj.a == 0` → `G`). Note: this changes pixels even where `Adj` equals `S` (Overlay of a pixel with its own gray darkens mid-tones) — Paint.NET's behavior.
   - `tintedGray` float rule: the product is one IEEE `Float` multiplication (no FMA, no `Double`), truncated toward zero by `Int(_:)`, then capped at 255 (`I·red ≤ 255·1.2 = 306`; `I·blue ≥ 0`, so no lower clamp is reachable). The factors are computed once on the CPU and passed to the kernel, never divided on the GPU (Metal fast-math division is not correctly rounded).
   - **`makeOutput`**: `blurred` (item 4) → `adjusted` (item 5) → `context.colorKernel("softenPortraitCompose").apply(extent: context.ciRect(context.outputRect), arguments: [input, adjusted, red, blue])`.

3. **`PaintDotMac/Core/Effects/Effects/Photo/RedEyeRemoval.swift`** (new).
   ```swift
   public struct RedEyeRemoval: ImageEffect {
       public init()
       public let id = "redEyeRemoval"
       public let name = "Red Eye Removal"
       public let category = EffectCategory.photo
       public static let hint = "Hint: For best results, first use the selection tools to select each eye"
       public var parameters: [EffectParameter] {
           [.init(id: "tolerance",  label: "Tolerance",             kind: .integer(range: 0...100, defaultValue: 70)),
            .init(id: "saturation", label: "Saturation percentage", kind: .integer(range: 0...100, defaultValue: 90), hint: Self.hint)]
       }
       public var alphaMode: EffectAlphaMode { .straight }
       public static func isRedEye(r: Int, g: Int, b: Int, tolerance: Int) -> Bool
       public static func replacementRed(r: Int, g: Int, b: Int, saturation: Int) -> UInt8
       public static func apply(_ c: ColorRGBA8, tolerance: Int, saturation: Int) -> ColorRGBA8   // the per-pixel definition; used by tests, mirrored by the kernel
       public func inputPadding(for values: EffectParameterValues) -> Int   // 0 (point op)
       public func makeOutput(input: CIImage, values: EffectParameterValues, context: EffectRenderContext) throws -> CIImage
   }
   ```
   - No shortcut; icon `.effect`; menu title "Red Eye Removal…"; step "Red Eye Removal". Runs with or without a selection (no alert, no disabled state).
   - **`isRedEye`** (exact integer form of 3.36's test): `let m = max(g, b); let mx = max(r, m); let mn = min(r, g, b)`; `return r − m > tolerance && 255·(mx − mn) >= 101·mx`. Proof sketch in a doc comment: `(int)(s·255) > 100 ⇔ ⌊255·Δ/max⌋ ≥ 101 ⇔ 255·Δ ≥ 101·max`; `max == 0`/`Δ == 0` can't pass because `r − m > tolerance ≥ 0` implies `r > m ≥ min`. A standalone check of all 32,640 `(max, min)` pairs found **no** case where 3.36's double expression disagrees with this integer test (asserted exhaustively in `RedEyeRemovalTests`).
   - **`replacementRed`**: `UInt8((299·r + 587·g + 114·b) · saturation / 100_000)` in `Int` (max 25,500,000) — the exact floor of `GetIntensity·255·saturation/100`. 3.36's double evaluation gives **1 less** on inputs where the exact value is an integer and the double rounds just below it (e.g. `(238, 40, 47)` at 90 %: exact 90, 3.36 89; 182 such triples at 90 %, 1,901 at 100 % across all of RGB, from a standalone script of both formulas) — *Open questions* 3.
   - **`makeOutput`**: `context.colorKernel("redEyeRemoval").apply(extent: context.ciRect(context.outputRect), arguments: [input, Float(tolerance), Float(saturation)])`.

7. **`PaintDotMac/Core/Rendering/Shaders/EffectKernels.metal`** (extend 0042's `// MARK: - Photo` section; `BlendOps.h` is already included by 0043). Three stitchable **color** kernels; bytes are recovered with `uint(rint(clamp(v, 0.0, 1.0) * 255))` per channel (alpha included), and results return `float4(bytes) / 255`:
   ```metal
   [[stitchable]] float4 glowCompose(coreimage::sample_t original, coreimage::sample_t adjusted);
       // o = bytes(original); a = bytes(adjusted) (rgb already integral from brightnessContrast; a.a = rint of the blur's float alpha)
       // return ScreenOp::apply(o, a) / 255   (ScreenOp handles a.a == 0 → o)
   [[stitchable]] float4 softenPortraitCompose(coreimage::sample_t original, coreimage::sample_t adjusted, float red, float blue);
       // o = bytes(original); I = (7471u·o.b + 38470u·o.g + 19595u·o.r) >> 16;
       // g = uint4(min(255u, uint(float(I) * red)), I, uint(float(I) * blue), o.a);   // one float multiply each, truncating float→uint conversion
       // return OverlayOp::apply(g, bytes(adjusted)) / 255
   [[stitchable]] float4 redEyeRemoval(coreimage::sample_t s, float tolerance, float saturation);
       // int r,g,b from bytes(s); int m = max(g, b), mx = max(r, m), mn = min(r, min(g, b));
       // if (r - m > int(tolerance) && 255 * (mx - mn) >= 101 * mx) r = (299*r + 587*g + 114*b) * int(saturation) / 100000;
       // return float4(r, g, b, bytes(s).a) / 255
   ```

## Edge cases

- **Uniform layers:** the blur of a uniform opaque layer is that layer exactly (no ties), so Glow/Soften Portrait results are exact: gray 100 → Glow defaults 166, Soften Portrait defaults (86, 78, 71). → `GlowReferenceTests.handValues`, `SoftenPortraitReferenceTests.handValues`, `PhotoV1xEffectsUITests.*`
- **Blur rounding ties** (e.g. `[0, 255, 0]` radius 1 → middle 127.5): GPU float may round either way; downstream gains (Contrast up to 100/1) amplify that — handled by the candidate rule, never by widening the tolerance. → `BlurStageCandidatesTests.tieDetected`, `PhotoV1xGoldenTests.glowGrid` (contrast 99)
- **Contrast 100** (`divide == 0` threshold branch) and **−100**: Glow with contrast 100, brightness 0: gray 100 → 100 (Screen with 0), gray 130 → 255; brightness −100, contrast −100 on gray 100 → 116. → `GlowReferenceTests.contrastExtremes`
- **Softness 0:** radius 0 → blur skipped byte-exactly; result exact on the GPU. **Lighting odd values:** `contrast(lighting:)` truncates toward zero (3 → −1, −3 → 1, −1 → 0, 1 → 0, ±20 → ∓10). **Warmth float quirk:** gray 100 at Warmth 5 → red 104 (not 105), at Warmth 6 → 105 (not 106); Warmth 0 → factors exactly (1, 1). → `SoftenPortraitTests.contrastFromLighting`, `.warmthFloatQuirk`, `PhotoV1xGoldenTests.softenPortraitWarmthExhaustive`
- **Transparent / sparse layers:** Glow on fully transparent tiles: blurred alpha 0 → `dst` unchanged → tiles stay unallocated, no step. Near opaque content Glow spreads a halo into transparent pixels (Paint.NET's "over-blur around the edges" tip; with `Da = 0`, `out = Adj`). Soften Portrait leaves `(0,0,0,0)` unchanged but replaces the color of alpha-0 pixels that carry color with their tinted gray (alpha stays 0). Red Eye ignores `(0,0,0,0)` (difference 0) and processes colored alpha-0 pixels. → `PhotoV1xEffectsIntegrationTests.sparseTilesStaySparseV1x`, `GlowReferenceTests.haloIntoTransparent`, `SoftenPortraitReferenceTests.colorUnderAlphaZero`
- **Semi-transparent pixels:** the composition uses both alphas (uniform (200,100,50,128): Glow defaults → (218,126,69,192), Soften Portrait defaults → (180,107,68,192)). → `GlowReferenceTests.semiTransparent`, `SoftenPortraitReferenceTests.semiTransparent`
- **Red Eye boundaries:** `difference == Tolerance` → unchanged (strict `>`); `(255,154,154)` passes the saturation test (⌊255·101/255⌋ = 101), `(255,155,155)` fails (100); Tolerance 100 recolors only pixels with `R − max(G,B) ≥ 101` (e.g. (255,0,0) → (68,0,0) at Saturation 90); Saturation 0 → red 0; nothing red in the image/selection → no step (H-6), and Repeat on already-fixed eyes adds no step. → `RedEyeRemovalTests.boundaries`, `PhotoV1xEffectsIntegrationTests.redEyeNothingRedAddsNoStep`, `PhotoV1xEffectsUITests.testRedEyeRemovalInSelection`
- **No selection for Red Eye Removal:** applies to the whole active layer (Paint.NET behavior), no alert. → `PhotoV1xEffectsUITests.testRedEyeRemovalHintAndNoSelection`
- **Tiny images (1×1, 1×N, N×1) and radius > size:** clamp-to-edge blur covers them; 1×1 Glow = Screen of the pixel with its adjusted self. → `PhotoV1xGoldenTests.tinyImagesV1x`
- **Chunk seams:** Glow radius 20 / Soften Portrait radius 30 across 256-px tiles and 512-px chunks: apron = radius, no seams. → `PhotoV1xGoldenTests.glowChunkSeamsInvisible`, `.softenPortraitChunkSeamsInvisible`
- **Hidden active layer, other layers, floating pixels, GPU unavailable / missing kernel:** 0031's session path ("Finish Pixels" first, hidden layer processed, other layers untouched, "The effect couldn’t be applied." with restore). → `PhotoV1xEffectsIntegrationTests.onlyActiveLayerChangesV1x`, `CoreImageBridgeTests.kernelsLoad`
- **Huge images (6000×4000, 65,535×1):** no integer overflow (kernel products ≤ 25,500,000 and 0026's `uint` bound); a radius-30 blur on a 65,535-px row stays within ±1. → `PhotoV1xGoldenTests.softenPortraitExtremeAspect`, `PhotoV1xPerformanceTests.*`

## Open questions

Decided as stated (recommended answers applied in this spec); please confirm and record in PRD.md §5.9/§12:

1. **Glow and Soften Portrait fidelity: build them from PaintDotMac's own Gaussian Blur (0041's definition), Brightness / Contrast (0031, already 3.36-exact) and Overlay/Screen with the normative composition (0026/0027), rather than porting 3.36's chains bit-exactly; ranges/defaults from the 3.36 source (Glow Radius 1–20 default 6, Brightness and Contrast −100…100 default 10; Soften Portrait Softness 0–10 default 5, Lighting −20…20 default 0, Warmth 0–20 default 10), since the docs give names but no numbers.** Consequences: on opaque interiors results stay within 5 (Glow) / 3 (Soften Portrait) of 3.36 at defaults; at image edges they follow 0041's clamp-to-edge; semi-transparent content follows 0041's correct alpha instead of 3.36's double-alpha fade; GPU ±1 holds per blur candidate (exact rounding ties in the blur are accepted either way, because Contrast can amplify a 1-step blur difference up to 100×). Paint.NET 5's dialog couldn't be inspected — please compare ranges/defaults if you have it. Recommended: yes, as specified.
2. **Red Eye Removal parameters: the docs name a single "Strength" control with no range or default, while the 3.36 source has "Tolerance" (0–100, default 70) and "Saturation percentage" (0–100, default 90) plus the hint "Hint: For best results, first use the selection tools to select each eye".** The mapping from Paint.NET 5's "Strength" to the 3.36 algorithm isn't documented. Recommended (applied): the 3.36 parameters, labels and hint, shown through a new optional schema `hint` line under "Saturation percentage"; no selection is required (no alert), as in Paint.NET.
3. **Red Eye Removal arithmetic: exact integer form (`255·Δ ≥ 101·max`; red = `⌊(299R + 587G + 114B)·Saturation / 100000⌋`) instead of 3.36's double evaluation.** The saturation test is identical for every input; the new red value is 1 higher than 3.36 on a small set of inputs where the exact result is an integer and 3.36's doubles round just below it (e.g. (238,40,47) at 90 %: 90 vs 89). A GPU can't reproduce 3.36's doubles. Recommended: yes.
