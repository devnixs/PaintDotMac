## User story

As a PaintDotMac user who relies on VoiceOver, Full Keyboard Access, Reduce Motion, or Increase Contrast, or who simply switches between Light and Dark mode, I can reach and operate every panel, dialog, and menu, hear a meaningful name and value for every control (including the canvas, color wheel, history and layer rows), see nothing animate when I asked for less motion, and every custom-drawn element looks right in both appearances while my image and its transparency checkerboard look exactly the same.

## Edge cases

- **Audit scope.** The audit runs on the app's current UI; if, on macOS 15 with Xcode 26, it only inspects the key window, each test makes the surface under test key first (panels via ⌃F6, dialogs are key when shown). The test asserts the expected surface root exists before auditing so an audit of the wrong window can't pass vacuously.
- **Full Keyboard Access off on the test Mac.** UI tests pass `-AppleKeyboardUIMode 2`; each Tab-order test first asserts that Tab moves focus from the first text field to a **button** (proof the mode took effect) and fails with a clear message otherwise. Without FKA, Tab cycles text fields and lists only (system behavior; covered manually).
- **Disabled controls** (e.g. Undo with no steps, Finish without pending edit, Delete Layer with one layer): skipped by Tab, still labelled and in the catalog check (`isEnabled == false` is allowed).
- **Dynamic labels**: layer names with colons or emoji (`"Layer: 1 🎨"`) → visibility label `"Visible: Layer: 1 🎨"` (the colon rule applies only to fixed labels and visible captions, never to user text). Layer names are never empty (0025's Layer Properties rules); the tests use the fixture names verbatim.
- **Canvas help at zoom extremes**: 1 % → "Zoom 1%.", 3200 % → "Zoom 3200%."; fractional fit zoom 33.33 % → "Zoom 33%."; no document layer (impossible: base layer always exists).
- **Wheel adjust wrap**: hue 357° + 5 → 2°; 2° − 5 → 357°; on a slot with value 0 the 0007 rule (value becomes 100) applies, the same as a click.
- **Appearance change while a dialog/panel is open**: NSViews redraw via `viewDidChangeEffectiveAppearance`; SwiftUI via environment; `ColorWheelImage` cache is not regenerated (appearance-neutral).
- **Increase Contrast toggled at runtime**: monitor publishes; views re-resolve without relaunch (manual 6; unit-tested via the monitor's resolve).
- **Reduce Motion toggled during an animation**: the running animation finishes; the next transition honors the new value.
- **High-contrast system appearances** (`.accessibilityHighContrastAqua/DarkAqua`): `ThemeColors.resolved` works with them and contrast minimums hold (tested).
- **Sheets over full-screen windows** and panels hidden without a document (0006 `hiddenWithoutDocumentWindows`): ⌃F6 with no visible panel does nothing (no crash).
- Every failure path is non-crashing: a role with an unresolved system color falls back to `labelColor`; an unknown `-UITestAppearance` value is ignored.

  3. **Dialogs.** New Image, Layer Properties, Resize Image, Resize Canvas (anchors "Top Left" … "Bottom Right"), JPEG Options, Settings, and three effect dialogs (Gaussian Blur, Levels, Curves): every control reads a name without a colon and its value; the Curves plot reads "Transfer Map, Luminosity: (0, 0), (255, 255)".
  4. **Keyboard only** (System Settings › Keyboard › Keyboard navigation ON; VoiceOver off). Use no mouse: ⌘N opens New Image with Width focused, Tab cycles Width → Height → Resolution → Cancel → OK, Return creates; ⌃F2 reaches the menu bar and every menu opens with arrows; ⌃F6 moves into the floating panels, Tab/arrow keys move inside, Space activates, Escape returns to the canvas and tool keys work again; every dialog's Escape cancels and Return confirms.
  5. **Reduce Motion** (Accessibility › Display › Reduce motion): ants stop immediately, the text caret stops blinking, Colors More/Less resizes without animation, History doesn't animate its scroll, reordering layers doesn't animate. Turn it off: all resume without relaunch.
  6. **Increase Contrast / Reduce Transparency** (Accessibility › Display): thumbnail and swatch borders, curve grid, and undone History rows become visibly stronger; the image, checkerboard, and on-canvas overlays look the same. With Reduce Transparency the floating panels and menus become opaque (system) and nothing in the app stays translucent.
  7. **Appearance switch with windows open**: switch Light ↔ Dark while a document, all panels, and the Curves dialog are open: chrome, surround, wheel outline, curve background/line, histogram background, thumbnail borders update live; the image, its checkerboard, and the wheel's colors do not change.

## Open questions

Recommended answers are applied in the spec above; the user should confirm or override each.

1. **Canvas VoiceOver value.** Keep the canvas value as the image size `"800 × 600"` (0001/0003 contract, UI tests depend on it) and put zoom, active layer, tool, and selection size into the accessibility help ("Zoom 100%. Layer: Background. Tool: Paintbrush."), or put all of that into the value? *Recommended: keep the value, add the help (applied).*
2. **What Increase Contrast changes.** Paint.NET has no equivalent. *Recommended (applied): system semantic colors adapt on their own; additionally decorative strokes (thumbnail/swatch/wheel/slider/histogram borders, curve grid and diagonal) switch from separator/tertiary colors to `secondaryLabelColor`, the active color slot outline becomes `labelColor`, undone History rows double their tint (15 % → 30 %) and use `labelColor` text; line widths and on-image overlays (ants, handles) stay unchanged.*
3. **Color wheel keyboard/VoiceOver interaction.** *Recommended (applied): the wheel is a VoiceOver adjustable element (increment/decrement = hue ±5°, wrapping) but is not in the Tab order; keyboard users edit hue/saturation with the Hue and Saturation sliders in the expanded (More ») Colors panel.*
4. **Curves plot keyboard editing** (deferred here by 0034). Paint.NET has no keyboard editing of curve points. *Recommended (applied): none in v1.0; the plot is not focusable, exposes its points as its value ("Transfer Map, Luminosity: (0, 0), (255, 255)"), and the channel pop-up, checkboxes, and Reset are reachable by Tab.*
5. **Keyboard model for the floating panels and lists.** *Recommended (applied): no new menu items or shortcuts; the standard macOS ⌃F6 ("Move focus to the floating window") moves focus into the panels, Escape returns to the document's canvas, ⌥⌘1–4 keep toggling visibility; in History and Layers, ↑/↓ move the focus ring between rows and Space/Return activates (jump to step / make layer active); Tab from a layer row reaches its visibility checkbox.*

## Out of scope

- New features or controls beyond accessibility of existing ones (e.g. keyboard nudging of curve points, a palette, rulers — 0052–0069).
- App icon and bundle size (0050); use-case acceptance tests (0051); dockable panels (0052, which must keep this spec's catalog and keyboard plans for panels).
- Localization (English only, PRD).
- Rewriting system UI (NSAlert, NSSavePanel, menus) — audited only for our own content; system-owned issues are handled as listed in the exclusion table.
- Changing the checkerboard or overlay colors with the appearance (they are deliberately neutral; checkerboard style is a 0046 setting).
- PRD edits (the orchestrator adds the new debug hooks to PRD §4 Testing and records the open-question answers in §12).
