### Facts verified by the spec author (2026-11-08; macOS 26.6, Xcode 26.3 build 17C529, XcodeGen 2.46.0)

A throwaway XcodeGen app configured like 0001 (custom `info: { path:, properties: }` plist, **not** `GENERATE_INFOPLIST_FILE`, deployment target 15.0, ad hoc signing) plus the icon document below established:

1. **Format choice: an Icon Composer `.icon` document, not an `AppIcon.appiconset`.** Xcode 26 compiles a `.icon` for a macOS 15 deployment target into **both** `Contents/Resources/Assets.car` (the layered icon for macOS 26 plus flattened 1024-px renditions; macOS 15 reads them through `CFBundleIconName`) and `Contents/Resources/AppIcon.icns` (a flattened fallback containing 16, 32, 128, and 256 px). The build printed no icon warnings. So one vector source covers macOS 15 and the Liquid Glass styles on macOS 26; an asset-catalog icon set would need committed PNGs for every size and would not adapt on macOS 26.
2. **XcodeGen 2.46 needs no special option.** A `AppIcon.icon` folder inside a `sources` path becomes a single `PBXFileReference` with `lastKnownFileType = wrapper.icon` in the app's Resources phase (not expanded into a group).
3. **actool's partial Info.plist is merged into the custom plist.** With `ASSETCATALOG_COMPILER_APPICON_NAME: AppIcon` in the target settings, the **built** `Info.plist` contains `CFBundleIconFile = AppIcon` and `CFBundleIconName = AppIcon` even though the source `PaintDotMac/Info.plist` (from `info.properties`) doesn't list them. Don't add those keys to `info.properties`.
4. **Release is not universal today.** `xcodebuild … -configuration Release -destination 'platform=macOS,arch=arm64'` builds **arm64 only** even with `ONLY_ACTIVE_ARCH = NO` and `ARCHS = arm64 x86_64`; `-destination 'generic/platform=macOS'` builds `x86_64 arm64`. The gate's `--release` step therefore produces a non-universal app, contradicting PRD §4 *Hardware*. This spec fixes it, because NF-8 must be measured on the universal app (the larger one).
5. **Sizes.** The universal Release build of the trivial test app with this icon: `Assets.car` 1,868,808 bytes, `AppIcon.icns` 53,007 bytes, whole bundle 2,071,901 bytes. The icon costs about 1.9 MB of the 30 MB budget. The source document is 1,282 bytes (three text files), well under AGENTS.md's 1 MB fixture limit.
6. **Icon Composer's previewer.** `/usr/bin/ictool` is an actool shim. The real one is `"/Applications/Xcode.app/Contents/Applications/Icon Composer.app/Contents/Executables/ictool"`: `ictool AppIcon.icon --export-image --output-file out.png --platform macOS --rendition Default --width 256 --height 256 --scale 1` (renditions `Default`, `Dark`, `ClearLight`, `TintedDark`). The design below was rendered in all four renditions and at 32 px: brush and frame stay hollow/solid as intended, centred, nothing clipped, legible at 32 px.
7. **Shapes must be filled outlines, not strokes** (lesson from Snapper 0051: stroked paths get their insides filled in the `Dark` rendition). The design below uses only filled paths; the frame is an even-odd ring.

The Release app I get at the end of every batch is universal and is guaranteed to stay under 30 MB.

### 4. Bundle check script (build tooling, new)

Create `.agents/skills/spec-implementer/scripts/check-app-bundle.sh` (bash, `set -euo pipefail`, executable). It is the single place that knows NF-8's measurement and the icon wiring, so the gate and a human can run it on any built `.app`.

```
check-app-bundle.sh <path/to/App.app> [--limit-bytes N] [--expect-archs "arm64 x86_64"] [--skip-size]
check-app-bundle.sh --self-test
```
- Defaults: `--limit-bytes 30000000` (NF-8's "30 MB", decimal megabytes as Finder shows them; Open question 5), `--expect-archs "arm64 x86_64"`.
- **Size** (unless `--skip-size`): the **logical size** of the bundle = the sum of `stat -f %z` over every regular file found by `find "$APP" -type f` (symlinks are not followed and not counted; macOS framework symlinks would otherwise double-count). Implemented as a function `bundle_bytes <dir>`. Pass when `bytes <= limit` (implemented as a function `size_ok <bytes> <limit>`, exit status only). Always print exactly one line `Bundle size: <X.XX> MB (<bytes> bytes) of <limit/1e6> MB limit` (MB = bytes / 1,000,000, two decimals). On failure also print the 10 largest files (`find … -type f -exec stat -f '%z %N' {} + | sort -rn | head -10`) and exit 1 with `check-app-bundle: FAILED: bundle is <bytes> bytes, over the <limit>-byte limit (NF-8)`.
- **Icon wiring** (always):
  - `plutil -extract CFBundleIconName raw Contents/Info.plist` is `AppIcon`, and `CFBundleIconFile` is `AppIcon`.
  - `Contents/Resources/AppIcon.icns` exists and is non-empty; `iconutil -c iconset -o <tmp>/x.iconset <icns>` succeeds and the iconset contains `icon_16x16.png` and `icon_128x128@2x.png` (the 16 px and 256 px fallbacks Xcode 26 generates; *Facts* 1).
  - `Contents/Resources/Assets.car` exists and `xcrun assetutil --info <car>` output contains the line fragment `"Name" : "AppIcon"`.
- **Metadata** (always): `CFBundleShortVersionString` matches `^[0-9]+\.[0-9]+\.[0-9]+$`; `CFBundleVersion` matches `^[1-9][0-9]*$`; `NSHumanReadableCopyright` is non-empty.
- **Architectures** (always): every arch in `--expect-archs` appears in `lipo -archs Contents/MacOS/<CFBundleExecutable>`. Print `Architectures: <lipo output>`.
- Each failure prints `check-app-bundle: FAILED: <reason>` to stderr and exits 1; success prints `check-app-bundle: OK` last and exits 0.
- **`--self-test`** (no app needed; exercises the pure size logic): in a `mktemp -d` directory, create `A.app/Contents/Resources/big` with `mkfile -n 29999999` (sparse, logical size 29,999,999) and a symlink `A.app/Contents/link → Resources/big`. Assert `bundle_bytes A.app == 29999999` (the symlink is not counted), `size_ok 29999999 30000000` passes, `size_ok 30000000 30000000` passes, `size_ok 30000001 30000000` fails, and after appending 2 bytes to another file `bundle_bytes` is `30000001`. Print `check-app-bundle self-test: OK` and clean up (trap on EXIT). Any mismatch exits 1 with `self-test: FAILED: <case>`.

## Edge cases

- **macOS 15 (deployment target):** no Liquid Glass. Xcode's flattened `AppIcon.icns` and the flattened renditions in `Assets.car` are used (*Facts* 1). Don't add a second, classic `AppIcon.appiconset`: two app icons with the same name conflict in actool.
- **Launch Services icon cache:** after rebuilding in place, Finder/Dock may keep the generic icon. That's a cache artefact; manual step 1 says how to refresh it.
- **Small sizes (16/32 px):** the frame ring is 56 px wide at 1024, ≥ 0.9 px at 16 px; the brush handle is ≥ 60 px wide. Verified legible at 32 px; check 16 px in manual step 3 rather than thickening shapes.
- **Name clash:** the document must be named `AppIcon.icon` to match `ASSETCATALOG_COMPILER_APPICON_NAME`. PaintDotMac has no other asset catalog. If a later spec adds `Assets.xcassets`, it must not contain an `AppIcon` set.
- **Hosted unit tests and `Bundle.main`:** the tests run inside the Debug app (0001), so `Bundle.main` is PaintDotMac.app and has the icon resources. The source-document tests locate the repo through `#filePath`, which works because tests run on the machine that built them.
- **Bundle size near the limit:** the check uses `<=`; exactly 30,000,000 bytes passes. Sparse files and APFS clones count by logical size (what a copy to another volume would need). Symlinks inside the bundle are not counted (their targets are counted once as regular files).
- **dSYM:** Release's `dwarf-with-dsym` puts `PaintDotMac.app.dSYM` **beside** the app, not inside, so it isn't counted. The check measures only the `.app` directory.
- **Debug bundle size:** Debug apps carry `PaintDotMac.debug.dylib` and aren't the shipped product; the Debug check uses `--skip-size`.
- **x86_64 build failure:** if the universal Release build fails only for x86_64 (Intel is best-effort, PRD §4), the gate fails; fix the code (usually an `#if arch` or SIMD issue), don't drop the arch silently. If it can't be fixed, stop and ask the user.
- **Missing tools:** `lipo`, `iconutil`, `plutil`, `xcrun assetutil` ship with Xcode/macOS; the gate's tool check fails clearly if one is missing.
- **Signing / codesign:** adding resources changes the ad hoc signature; `codesign --verify --deep --strict` must still pass (verified on the throwaway app).
- **`.ora` document icon:** none is declared (Open question 2). With PaintDotMac as the `Default` handler (0028), macOS composes a document icon from the app icon and the extension; if Krita is the default handler on the user's Mac, Finder shows Krita's icon. Neither is a bug.

## Open questions

Each one has the recommended answer **applied** in this spec; the batch owner confirms or changes it with the user and records it in PRD.md (§4/§6 NF-8/§12) before implementation.

1. **Icon design.** Recommended: an original motif — a white paintbrush in front of a white rounded-square canvas frame on deep orange `#D9480F`, as an Icon Composer `.icon` (Liquid Glass on macOS 26, flattened fallback on macOS 15). Paint.NET's logo and trade dress are not used. Accept, or name a different motif/colour?
2. **`.ora` document icon.** Recommended: no custom document icon in v1.0 (no `UTTypeIcons`/`CFBundleTypeIconFile`); macOS composes one from the app icon when PaintDotMac is the default handler. Add a dedicated `.ora` document icon (later spec) instead?
3. **Version policy.** Recommended: `MARKETING_VERSION` semantic `X.Y.Z`, set to `1.0.0` by this spec (M7 = v1.0); `CURRENT_PROJECT_VERSION` a positive integer, stays `1`; both only in `project.yml`, bumped by hand by the user, never automatically; tests check only their shape. Keep `0.x` until the user declares v1.0 instead?
4. **About panel text.** Recommended: copyright `© 2026 Thera Engineering` (matching the bundle ID and the author's other app), and no credits text. Add a credits line such as "Inspired by Paint.NET. Not affiliated with dotPDN LLC."?
5. **NF-8 measurement.** Recommended: "30 MB" = 30,000,000 bytes (decimal, as Finder shows), measured as the summed logical size of all regular files in the **universal Release** `.app` (symlinks not counted, dSYM excluded), gated in `quality-gate.sh --release`. Use 30 MiB (31,457,280 bytes) or on-disk allocated size instead?

## Out of scope

- A custom `.ora` document icon, DMG/installer art, notarisation, or any distribution packaging (PRD §2.2 non-goal: public distribution).
- Automatic version bumping or release tagging (none in this project; spec-implementer SKILL.md:196).
- In-app use of the icon (toolbar, Settings window from 0046, onboarding) — nothing in the PRD asks for it.
- Dead-code/size optimisation work beyond measuring: if the bundle is already far under 30 MB (expected ≈ a few MB), nothing is optimised here. If it is over, that is a defect to fix in this spec before closing it.
- Accessibility and appearance (0049) and the use-case acceptance tests (0051).
