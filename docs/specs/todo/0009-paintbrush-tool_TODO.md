Decided (PRD D-38): strokes are continuous, so Paint.NET 5's *Spacing*, *Smoothing*, and *Fill Style* (patterns) options are not in v1.0; brush tools show a brush-outline cursor. Pressure is TOOL-D (P1, D-14). Paint.NET's Ctrl+`[`/`]` ×5 step has no Mac equivalent because ⌘[ / ⌘] are Rotate (§5.12, D-12). Paint.NET's Paintbrush is the start tool, and so is PaintDotMac's once this spec lands (§5.3, D-35).

## User story

As a PaintDotMac user, I start with the Paintbrush active (or press **B**), see a circle the size of my brush following the pointer, choose a brush width, hardness, and antialiasing in the tool options bar, and drag on the canvas to paint smooth strokes in the primary color (right-drag or Control-drag for the secondary color). Overlapping parts of one stroke never get darker, `[` and `]` shrink and grow the brush, and each stroke is one "Paintbrush" step that ⌘Z undoes.

## Scope & changes

### Core (pure Swift, unit-tested; no AppKit/SwiftUI imports)

- **`PaintDotMac/Core/Rendering/BlendOps.swift`** (new) — straight-alpha per-pixel blend functions keyed by `BlendMode`.
  - API (0011 and 0012 already call these names):
    ```swift
    enum BlendOps {
        /// round(a·b / 255) exactly, Paint.NET's rounding: t = a·b + 128; ((t >> 8) + t) >> 8
        static func mul255(_ a: UInt8, _ b: UInt8) -> UInt8
        /// src.a is first scaled by opacity (src.a = mul255(src.a, opacity)), then the mode's function is applied.
        static func blend(_ mode: BlendMode, dst: ColorRGBA8, src: ColorRGBA8, opacity: UInt8 = 255) -> ColorRGBA8
        static func normal(dst: ColorRGBA8, src: ColorRGBA8) -> ColorRGBA8
    }
    ```
    `blend` switches over `BlendMode` (exhaustive, `.normal` only today; 0026/0027/0059 add cases and one function each here). 0012's `CPUCompositor` calls `blend(layer.blendMode, dst:, src:, opacity: layer.opacity)`; the brush calls it with `opacity` 255 and the coverage already folded into `src.a`. Note: `mul255(a, b)` equals `(a·b + 127) / 255` for all inputs (no ties, since 255 is odd).
  - **Normal (exact integer formula; Paint.NET `UserBlendOps.NormalBlendOp` is Porter-Duff source-over in straight alpha).** With `Sa, Da ∈ 0…255`, channels `Sc, Dc ∈ 0…255`, all arithmetic in `UInt32` (max intermediate ≈ 3.4·10⁷), `/` = truncating integer division:
    - If `Sa == 0`: return `destination` **unchanged** (bit-for-bit, including its RGB when `Da == 0`).
    - `fa = Sa·255 + Da·(255 − Sa)` (this is `outA·255`, range 1…65025 here)
    - `outA = (fa + 127) / 255`
    - `outC = (Sc·Sa·255 + Dc·Da·(255 − Sa) + fa/2) / fa` for each of R, G, B
    - Result `(outR, outG, outB, outA)`.
    Paint.NET's own fixed-point approximation is within ±1 of this over an opaque destination; see 0026/0027 for the general bound; this formula is the normative one for PaintDotMac and for the 0024 Metal parity (±1).

    - The returned `PixelRect?` is the changed pixel region (for redraw), `nil` if nothing changed.
  - Pure helpers, `static` and separately tested: `BrushEngine.coverage(distance:options:) -> UInt8` (the profile below), `BrushEngine.distance(from:toSegment:_:) -> Double`, `BrushEngine.snappedCenter(_:width:) -> CGPoint` (aliased snapping).
- **Brush model (normative; tests compute the same values by hand / in a test-target oracle).**
  - *Coordinates.* Canvas space as delivered in `ToolEvent.location` (0006: image pixels, `Double`, top-left origin, y down): integer values lie on pixel **corners**; pixel `(i, j)` covers `[i, i+1) × [j, j+1)` and its center is `(i + 0.5, j + 0.5)`. Events whose point is non-finite (NaN/∞) are ignored.
  - *Dab and sweep (spacing).* The dab is a disc of radius `r = width / 2` centred on the pointer. A stroke is the polyline through the mouse-down point and every subsequent drag/up point (no smoothing, no interpolation between events other than straight segments). Instead of stamping dabs at a fixed spacing, each segment is swept continuously: a pixel's coverage from a segment is `profile(d)` where `d` = Euclidean distance from the pixel center to the closed segment (`A == B` → distance to the point). This is exactly the limit of dab stamping as spacing → 0, so there is no spacing parameter and no scalloping at any width; Paint.NET 5's Spacing option is not in v1.0 (PRD D-38).
  - *Distance to segment.* `if A == B { d = |P − A| } else { t = clamp(((P − A)·(B − A)) / |B − A|², 0, 1); d = |P − (A + t·(B − A))| }`, in `Double`.
  - *Antialiased profile* (`antialiasing == true`): `R = r + 0.5`, `h = hardness / 100`.
    - edge term `e = clamp(R − d, 0, 1)` (a one-pixel antialiased edge centred on the disc boundary)
    - softness term: if `hardness == 100`, `s = 1`; else `t = clamp((R − d) / (R·(1 − h)), 0, 1)`, `s = t·t·(3 − 2t)` (smoothstep)
    - `c = min(e, s)`; coverage byte `cov = UInt8(floor(c·255 + 0.5))`.
    - Both terms are non-increasing in `d`, so the max over all segments equals `profile(min distance to the whole polyline)` — the property the tests rely on.
  - *Aliased profile* (`antialiasing == false`; hardness ignored): `w = max(1, round(width))` (round half away from zero, so 2.5 → 3), `r = w / 2`. Every polyline point is first snapped with `snappedCenter`: odd `w` → `(floor(x) + 0.5, floor(y) + 0.5)` (pixel center); even `w` → `(floor(x + 0.5), floor(y + 0.5))` (nearest pixel corner). Coverage is 255 when `d² ≤ r²` (distance to the snapped segment), else 0. Consequences used by tests: w=1 → one pixel; w=2 → a 2×2 block; w=3 → a full 3×3 block; w=4 → a 4×4 block minus its 4 corner pixels.
  - *Stroke coverage buffer (no darkening within a stroke).* For each pixel the stroke keeps `strokeCov = max` of all coverages it received so far (`StrokeCoverageBuffer.raise`). The layer pixel is always recomputed from the pixel's **before-stroke** value, never from the partially painted value, so a pixel passed over twice in one stroke gets exactly the same result as a pixel passed over once. Separate strokes do accumulate (each starts from the then-current layer).
  - *Clip.* `effCov = clip == nil ? strokeCov : BlendOps.mul255(strokeCov, clip.coverage(x, y))`, applied at compose time (the mask is fixed for the stroke). If `effCov == 0` the pixel stays exactly `before` and `compose` is not called.
  - *Compose (Paintbrush rule).* `Sa = BlendOps.mul255(color.a, effCov)`; `src = (color.r, color.g, color.b, Sa)`; `layerPixel = BlendOps.blend(options.blendMode, dst: before, src: src)`. With `Sa == 0` the pixel stays exactly `before`.
  - *Region.* Each segment only visits pixels in its bounding box expanded by `R + 1` (antialiased) or `r + 1` (aliased), computed in `Double` and clamped to `[0, canvasWidth) × [0, canvasHeight)` **before** converting to `Int`, so far-off-canvas points cannot overflow. A pixel is rewritten only when its `strokeCov` increased. Segments entirely outside the canvas change nothing.
  - *Before-snapshot.* `begin` keeps `before = surface` (0008's capture pattern; tiles are shared copy-on-write, so only tiles the stroke writes are ever duplicated) and the stroke records `touchedTiles` (the tiles it wrote). `makeTileDiff` passes `touchedTiles` as `candidates`, so the diff holds before/after only for touched tiles whose content differs (an absent tile is `nil`); a touched tile that ends equal to its before content is not recorded (NF-4).
  - *Writes* go through `TiledSurface.setPixel(_:at:)` (or a tile-level write that bumps `generation`), so 0003's renderer sees the tiles in `changedTiles(since:)`. The per-segment work may be split across tiles with `DispatchQueue.concurrentPerform`, provided the result is bit-identical to the sequential order (it is, since each pixel depends only on its own before value and coverage).

## Edge cases

- **Width extremes:** width 1 (antialiased at a pixel corner covers 4 pixels at coverage 75 each); width 2000 on a 4000×3000 canvas (one dab touches ~3.1 M pixels; must complete without crash and be undoable). Width larger than the canvas is fine.
- **Sub-integer widths** (e.g. 6.5) are honoured only when antialiased; aliased rounds (2.5 → 3, 2.4 → 2).
- **Hardness 0** gives a smoothstep cone reaching 0 at `R`; **hardness 100** gives only the one-pixel edge ramp.
- **Single click** (down + up at the same point, no drag) paints one dab and is one history step.
- **Points off canvas / far off canvas** (e.g. −1e9) and **strokes entirely outside** change nothing and add no history; strokes that leave and re-enter the canvas paint only the on-canvas parts. NaN/∞ points are ignored.
- **1×1 image:** a dab anywhere covering the pixel center paints it; no out-of-bounds access.
- **Color alpha 0** (primary set to transparent): no pixel changes, no history step. **Semi-transparent color** over a semi-transparent pixel follows the Normal formula exactly (straight alpha; RGB of a fully transparent destination is ignored because `Da = 0`).
- **Fully transparent/absent tiles:** painting into a sparse tile allocates it; cancel/undo returns it to absent (or equal-to-transparent) state; tiles touched but unchanged are not in the diff.
- **Tile boundaries** (x or y = 256k) — no seams, no double processing.
- **Hidden active layer:** painting still happens (Paint.NET behaviour); no special case.
- **Mouse-down while a stroke is active** (second button pressed) is ignored; the original button decides the color until mouse-up.
- **Undo/redo, tool switch, save, or document switch mid-stroke:** `commit(context:)` runs first (0008 `prepareForNavigation`, 0006 `deactivate`/`setContext`, this spec's save hook). Escape runs `cancel(context:)`. Never leaves half-applied pixels without a history step.
- **Pointer leaves the canvas view:** the outline is hidden; a stroke in progress continues (the drag owns the mouse) and off-canvas segments paint nothing.
- **Tiny outline:** at 1% zoom a width-2 brush is 0.02 device pixels: below `minimumViewDiameter` only the crosshair shows. **Huge outline:** width 2000 at 3200% is far larger than the view; `ToolOverlayView` draws the clipped circle with no allocation proportional to its size.
- **Options changed mid-stroke** (`[`/`]`, bar edits) apply to the next stroke.
- **Clip mask with coverage 0 everywhere:** no change, no history step.
