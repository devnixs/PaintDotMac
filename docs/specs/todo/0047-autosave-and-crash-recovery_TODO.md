## Context

Not yet implemented; no application code exists. What the earlier specs leave in place:

- `PaintDotMac/Document/PaintDocument.swift` (0001/0005): `override class var autosavesInPlace: Bool { false }` (permanent, `docs/specs/todo/0001-project-and-document-shell_TODO.md:150`) and the interim `override var autosavingFileType: String? { nil }` (`docs/specs/todo/0005-new-image-and-png-save_TODO.md:23,131`), so no autosave is ever written. 0005's test `PaintDocumentSavingTests.autosaveSettings` asserts `autosavingFileType == nil` (`0005…:248`).
- 0008 (`docs/specs/todo/0008-history-stack-and-undo-bridge_TODO.md:220-222`): `hasUndoManager = false`; the history is the single source of the edited state: `undoBridge.onEditedChange = { isEdited in super.updateChangeCount(isEdited ? .changeDone : .changeCleared) }`. `.changeDone` on every edit is what makes `NSDocument.hasUnautosavedChanges` true. `changeCountToken(for:)`/`updateChangeCount(withToken:for:)` mark the saved step only for `.saveOperation`/`.saveAsOperation`; autosave never marks saved (test `autosaveAndSaveToDoNotClear`, `0008…:363`). The `save(to:ofType:for:completionHandler:)` override commits the active tool's pending edit before `super`; 0020 turns that call into `undoBridge.prepareForSave()` (`0020…:151-153`).
- 0020: while pixels float, the **layer already shows them** (`0020…:121`); save never adds "Finish Pixels". 0038/0040: an uncommitted line/curve, shape, or text is rendered into the live layer through `context.updateImage` (`0038…:180`, `0040…:152`). So `undoBridge.state.image` is always "what the user sees".
- 0028: `OpenRasterCodec.encode(_:modificationDate:processorCount:memoryCap:) throws(ImageCodecError) -> Data` and `decode` (`0028…:203-206`) store layers, names, visibility, opacity, blend mode, DPI (`xres`/`yres`), and the active layer (`selected="true"`, `0028…:239`). `PaintDocument.read(from:ofType:)` sniffs ZIP data, so an `.ora` reads correctly even with another type name (`0028…:484`). `read` ends with `undoBridge.reset(state:base: .openImage)` (clean).
- 0029 (`0029…:157-162`): the save funnel maps `.autosaveInPlaceOperation`/`.autosaveElsewhereOperation`/`.autosaveAsOperation` → `SaveOperationKind.autosave`; `SavePlan` never asks to flatten and never shows the JPEG dialog for `.autosave` (`SavePlanTests.autosaveNeverPrompts`, `PaintDocumentSavingTests.autosaveDoesNotPrompt`).
- 0031 (`0031…:257,379`): `UndoBridge.isBusy` is true while an effect/adjustment dialog previews into the live state; "0047 must skip crash-recovery autosave while `UndoBridge.isBusy`".
- 0001: `AppDelegate.applicationShouldOpenUntitledFile(_:) == false` (no untitled document at launch), `applicationSupportsSecureRestorableState(_:) == true`. Every UI-test launch passes `-ApplePersistenceIgnoreState YES` first (`UITestApp.launch`, `0001…:210-214`), and the scheme's test action passes it to the hosted unit tests (`0001…:74`). `LaunchOptions` is a pure, always-compiled parser whose use is gated by `#if DEBUG` (`0001…:90-95`).

What is missing: NF-5. Nothing is written while the user works, so a crash, a `kill -9`, or a power loss loses every unsaved change.

Mechanics this spec relies on (AppKit, no custom recovery UI): with `autosavesInPlace == false`, `NSDocumentController.autosavingDelay > 0` makes `NSDocument` periodically **autosave elsewhere** documents whose `hasUnautosavedChanges` is true. It writes `autosavingFileType` to a file in the user's "Autosave Information" directory (`FileManager.url(for: .autosavedInformationDirectory, in: .userDomainMask, …)`; not sandboxed, so `~/Library/Autosave Information/`) and records it in `autosavedContentsFileURL`. The document's restorable window state records `fileURL` and `autosavedContentsFileURL`. When the app is relaunched after it died without quitting normally, AppKit's window restoration calls `NSDocumentController.reopenDocument(for: fileURL /* nil when untitled */, withContentsOf: autosavedContentsFileURL, display:)`, which builds the document through `init(for:withContentsOf:ofType:)`. `-ApplePersistenceIgnoreState YES` disables both reading and writing that restorable state, so **no recovery happens in a launch that passes it** (all ordinary tests); window restoration does not consult `applicationShouldOpenUntitledFile`, so 0001's "no untitled document at launch" rule is unaffected (an empty launch still opens nothing; a crash-recovery launch opens exactly the recovered documents).

## User story

As a PaintDotMac user, if the app crashes, is force-quit, or the Mac loses power while I have unsaved work, relaunching the app brings back every document window I had open, with my layers and pixels as they were at most about 30 seconds before the crash, still marked as unsaved, untitled documents still untitled, and saving one writes its original format. Autosaving never interrupts me with a dialog or a stall while I paint.

   public enum AutosaveDecision: Equatable, Sendable { case write, skip(AutosaveSkipReason) }

       /// NSDocumentController.autosavingDelay in Release and in Debug without the launch hook (Open question 1).

   }

## Edge cases

- **Clean document:** `hasUnautosavedChanges` is false; AppKit doesn't autosave it, no file exists, and restoration after a crash reopens a titled one from its own file (AppKit's normal behavior) and an untouched new image not at all (nothing to lose, D-30).
- **Edit during an in-flight autosave:** the snapshot is the state at the start; the edit's `.changeDone` sets `hasUnautosavedChanges` again, so the next tick writes it. → `.snapshotIsolatedFromLaterEdits`
- **Save or undo-to-clean while an autosave is being written:** the completion sees the clean document and removes the file it just wrote. → `.cleanDuringWriteRemovesAutosave`
- **Effect dialog open for longer than the delay:** every tick skips and retries every 2 s; a single retry is pending at a time (`isAutosaveRetryScheduled`). After OK the commit's `.changeDone` reschedules AppKit's autosave; after Cancel the state is unchanged and the earlier autosave (if any) is still valid. → `.busySkipsAndRetries`, `.singleRetryPending`
- **Closing while a retry is pending:** the retry does nothing. → `.retryAfterCloseDoesNothing`
- **Huge images:** snapshot is O(tiles); the encode may take seconds off-main (0028's concurrency cap) and the UI stays responsive (NF-1 — manual check 2). Memory: the snapshot pins at most one extra copy of the tiles that change while the write runs.
- **Encoding failure** (`ImageCodecError`, disk full, permissions): the error goes to AppKit's autosave completion, no alert, document stays edited, `hasUnautosavedChanges` stays true, next tick retries. → `.writeFailureKeepsUnautosaved` (inject a failing encoder via an internal `autosaveEncoder: @Sendable (LayeredImage) throws -> Data` seam, default `OpenRasterCodec.encode`)
- **Corrupt or truncated autosave file at recovery:** `init(for:withContentsOf:ofType:)` throws; no document, no crash. AppKit writes autosaves atomically, so a crash mid-write leaves the previous autosave intact. → `AutosaveRecoveryTests.corruptAutosaveFails`
- **Original file deleted or changed on disk before recovery:** the document is still recovered from the autosave and keeps its `fileURL`; ⌘S recreates/overwrites it with `NSDocument`'s standard "changed by another application" handling (Open question 3). → `AutosaveRecoveryTests.missingOriginalStillRecovers`
- **Recovered JPEG document:** `fileType` is `public.jpeg`; ⌘S goes through 0029's JPEG Options dialog (and the FMT-A confirmation if it has several layers) as for any JPEG. → `.recoveredJPEGKeepsType`
- **Original extension not readable** (e.g. a format removed later): `recoveredFormat` falls back to OpenRaster. → `AutosavePolicyTests.recoveredFormat`
- **Recovery launches and 0001's no-untitled rule:** restoration never calls `applicationShouldOpenUntitledFile`; an empty normal launch stays empty. → existing `LaunchUITests`, `.testIgnoreStateRestoresNothing`
- **User holds Shift at launch / "Close windows when quitting" preference:** AppKit-defined. Crash restoration is AppKit's; Shift discards restoration, leaving autosave files to AppKit (Open question 4). Manual check 1.
- **Hosted unit tests** write into the real `~/Library/Autosave Information`; every test closes its documents (which deletes their autosave files) in a `defer`, and asserts the file is gone.

## Open questions

Recommended answers are applied in this spec; each needs the user's confirmation (PRD silent).

1. **Autosave interval.** How often should PaintDotMac write the crash-recovery autosave? Recommended: every 30 seconds after a change (`autosavingDelay = 30`), so at most ~30 s of work is lost; not configurable in Settings in v1.0.
2. **What recovery restores.** Recommended: the layers (names, visibility, opacity, blend modes, pixels), DPI, and active layer exactly as displayed at the last autosave — floating (moved/pasted) pixels and an uncommitted line/shape/text are recovered rendered into their layer; the selection, the undo history (the recovered document starts with one "Open Image" step), and the editable state of floating pixels/shapes/text are not recovered, because `.ora` doesn't store them. While an adjustment/effect dialog is previewing, autosave is skipped, so the recovered image never contains an un-applied preview.
3. **Original file changed or deleted before recovery.** Recommended: the recovered autosave wins; the document keeps its original location, and ⌘S writes there with macOS's standard "the file has been changed by another application" warning when applicable.
4. **No own recovery UI.** Recommended: rely on macOS window restoration only — no "Recover documents?" dialog and no File menu command for orphaned autosaves in v1.0. If the user discards restoration (for example by holding Shift at launch), the autosaves are not offered.

## Out of scope

- Asynchronous regular saves and save progress → 0048 (performance pass). Only autosave writes off-main here.
- In-place autosave / Versions (`autosavesInPlace` stays `false`, D-6) and any autosave of history, selection, or tool state.
- A Settings option for the interval or for disabling autosave (APP-8 lists none; 0046).
- Disk-backed history (H-4) → 0062.
- Cleaning up autosave files of other apps or orphaned PaintDotMac autosaves from earlier sessions.
