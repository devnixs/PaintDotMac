### Paint.NET 3.36 behaviour (transcribed)

**Local histogram (`LocalHistogramEffect.RenderRect`, shared by Median, Reduce Noise, Outline — and Sharpen, 0042).** For output pixel `(x, y)` and radius `r`, the samples are the source pixels `(x+u, y+v)` for every offset with `u² + v² ≤ cutoff`, `cutoff = ((2r+1)² + 2) / 4` (integer), **that lie inside the canvas** (offsets outside are not counted; `area` = number of counted samples, so it shrinks at the edges). Four 256-bin histograms `hb`, `hg`, `hr`, `ha` (B, G, R, A of the **straight** source). The sliding-window update is an optimization equal to this direct definition. The effect's `Apply(src, area, hb, hg, hr, ha)` gives the output pixel. `r = 0` → `cutoff 0` → the pixel alone (`area 1`). Areas (interior): r 1 → 9, 2 → 21, 3 → 37, 10 → 349, 200 → 126,309 (`Sharpen.diskOffsets(radius: 200).count`; computed by the test, not hard-coded elsewhere).

**`GetPercentile(p, area, h)`** per channel (B, G, R, A, each with its own histogram): `minCount = area · p / 100` (integer); `b = 0; count = 0; while b < 255 && h[b] == 0 { b += 1 }; while b < 255 && count < minCount { count += h[b]; b += 1 }; return b`. Closed form (0042's derivation generalized from `k = area/2` to `k = minCount`): with the channel's samples sorted `s₁ ≤ … ≤ s_area`, **`P(k) = k == 0 ? s₁ : min(255, s_k + 1)`** (the `+1` quirk; `P` is non-decreasing in `k`).

**Median** (`MedianEffect`): `Apply = GetPercentile(percentile, area, hb, hg, hr, ha)` — all four channels including alpha. So: `p = 0` → per-channel minimum; `p = 50` → median `+ 1`; `p = 100` → `min(255, max + 1)`; a flat area of 100 becomes 101; a fully transparent neighbourhood `(0,0,0,0)` becomes `(1,1,1,1)` whenever `minCount ≥ 1`.

**Reduce Noise** (`ReduceNoiseEffect`): `strength = −0.2 · Strength` (Double). `Apply(color, area, …)`:
```
rc = Σ_{i < color.R} hr[i];  gc = Σ_{i < color.G} hg[i];  bc = Σ_{i < color.B} hb[i]      // samples strictly below the pixel's own value
rc = (rc · 255) / area;  gc = (gc · 255) / area;  bc = (bc · 255) / area                   // integer division
normalized = FromBgr(bc, gc, rc)                                                            // alpha 255
I = ((0.114 · B) + (0.587 · G) + (0.299 · R)) / 255.0                                       // color.GetIntensity(), Double, straight values
lerp = strength · (1 − 0.75 · I)                                                            // ≤ 0
out.C = ClampToByte(C + lerp · (normalized.C − C))   for C ∈ {B, G, R, A}  (normalized.A = 255)
ClampToByte(x: Double) = x > 255 ? 255 : x < 0 ? 0 : (byte)x   // truncation toward zero
```
Because `lerp ≤ 0`, each channel is pushed *away* from its local rank (a pixel darker than most neighbours gets darker, brighter gets brighter, a flat area brightens slightly — the docs' "subtle brightening"), and alpha is pushed away from 255 (semi-transparent pixels lose a little alpha; alpha 0 and 255 are unchanged). `Strength 0` → identity.

**Outline** (`OutlineEffect`), `I = Intensity`: `minCount1 = area · (100 − I) / 200`, `minCount2 = area · (100 + I) / 200` (integer). For each color channel `C ∈ {B, G, R}` with histogram `h`:
```
c1 = 0; count = 0
while c1 < 255 && h[c1] == 0 { c1 += 1 }
while c1 < 255 && count < minCount1 { count += h[c1]; c1 += 1 }
c2 = c1
while c2 < 255 && count < minCount2 { count += h[c2]; c2 += 1 }      // count carries over
out.C = 255 − (c2 − c1)
```
Closed form: `out.C = 255 − (P(minCount2) − P(minCount1))` (proved in *Scope* item 7). Alpha (**3.36 quirk: the skip loop reads the blue histogram**):
```
a1 = 0; count = 0
while a1 < 255 && hb[a1] == 0 { a1 += 1 }                            // hb, not ha
while a1 < 255 && count < minCount1 { count += ha[a1]; a1 += 1 }
a2 = a1
while a2 < 255 && count < minCount2 { count += ha[a2]; a2 += 1 }
out.A = a2                                                            // not 255 − (a2 − a1)
```
Consequences: flat areas → white `(255,255,255)`, edges darker; on opaque images (`ha` all at 255) `out.A = 255` whenever `minCount2 ≥ 1` (always, except a 1-pixel neighbourhood); a fully transparent neighbourhood → `(255,255,255,1)`; a flat `(R 0, G 0, B 200, A 100)` area → alpha 255 (the alpha samples below the blue minimum are never counted), whereas with `R 200, B 0` it gives alpha 101.

**Relief** (`ReliefEffect : ColorDifferenceEffect`): `r = angle · 2π / 360`, `dr = π / 4`, weights `[fy][fx]` (row 0 = above, y down) exactly as 0044's directional weights **except `w[1][1] = 1`**:
```
w00 = cos(r + dr)   w01 = cos(r + 2dr)   w02 = cos(r + 3dr)
w10 = cos(r)        w11 = 1              w12 = cos(r + 4dr)
w20 = cos(r − dr)   w21 = cos(r − 2dr)   w22 = cos(r − 3dr)
```
`RenderColorDifferenceEffect`: per channel `sum = Σ w[fy][fx] · Double(C(x−1+fx, y−1+fy))` accumulated `fy` outer, `fx` inner; `(int)sum` (toward zero), clamped 0…255; output `(r, g, b, 255)`; alpha ignored. The eight outer weights sum to 0 in exact arithmetic, so Relief = original + Edge Detect's signed response. In Double, the sum for a flat area is not exactly the value: at the default 45° a flat 40 gives `39.999999999999993` → **39** (also at 90°, 180°, −180°, 137.25°; 0°, 25°, −63° give 40 — values computed with an independent script while writing this spec); a GPU `float` evaluation lands on either side, hence ±1 (*Open questions* 4). 3.36 skips out-of-canvas taps; this spec clamps (0044 *Open questions* 2, applied unchanged).

## User story

As a Paint.NET switcher, I open **Effects ▸ Noise ▸ Median…** (Radius 10, Percentile 50) to remove speckles from a scan and lower Percentile to pick darker colors; **Effects ▸ Noise ▸ Reduce Noise…** (Radius 10, Strength 0.40) to clean up a noisy photo; **Effects ▸ Stylize ▸ Outline…** (Thickness 3, Intensity 50) to turn a flat drawing into white with colored edges; and **Effects ▸ Stylize ▸ Relief…** (Angle 45°) to give a picture a lit, embossed-in-color look. Each previews live, Cancel restores the image exactly, OK adds one undoable step named after the effect, ⌘F repeats it, a selection limits it with soft edges, and even Radius 200 stays cancellable.

## Scope & changes

Cross-cutting rules (unchanged from 0031/0041): one file per effect conforming to `ImageEffect` with a schema, registered in `EffectRegistry.standard`; no hand-written dialog; every pixel change goes through 0031's `EffectSessionController` → `UndoBridge`; straight 8-bit sRGB storage; rendering off the main actor in 0031's runner; `Core` imports no AppKit/SwiftUI (Core Image, Metal, simd allowed, D-19).

**Why a new GPU path.** 0042's `sharpen` CI kernel re-reads the whole disk for every pixel (≈ 9 · area taps). At Radius 200 (area 126,309) that is ≈ 1.1 million taps per output pixel — minutes for one 512×512 chunk — so Median/Reduce Noise/Outline (radius up to 200) need Paint.NET's own **sliding histogram** on the GPU: a Metal compute function wrapped in a `CIImageProcessorKernel` (the option 0042 item 6 already allows for Sharpen). The framework additions are minimal and additive: `CoreImageBridge` also builds compute pipelines from the same library, and `EffectRenderContext` hands them out. `EffectRunner`, `EffectTileRenderer`, `EffectSessionController` and the dialog are **unchanged**. *If 0042's implementer already introduced a `CIImageProcessorKernel` local-histogram path (see 0042's Verification status), extend that type into item 2's API instead of creating a second one.*

2. **`PaintDotMac/Core/Rendering/LocalHistogramKernel.swift`** (new) — `public final class LocalHistogramKernel: CIImageProcessorKernel` (`Core` may import CoreImage/Metal) and its parameter type:
   ```swift
   public enum LocalHistogramMode: Int32, Sendable { case identity = 0, median = 1, reduceNoise = 2, outline = 3 }   // identity: test-only orientation check

       static var segmentLength: Int { 64 }   // output pixels per thread along a row (tunable, see item 11)
       /// Builds the processor output for one render region. `input` = the bridge's input image (straight, clamped to extent).
       static func makeOutput(input: CIImage, parameters: LocalHistogramParameters, context: EffectRenderContext) throws -> CIImage

   ```
   - `makeOutput`: `let pipeline = try context.computePipeline(pipelineName)` (item 3); `try apply(withExtent: context.ciRect(context.outputRect), inputs: [input], arguments: ["pipeline": pipeline, "mode": …, "radius": …, "percentile": …, "strength": …, "intensity": …, "inputRect": CIVector(x: in.minX, y: in.minY, z: in.width, w: in.height), "canvas": CIVector(x: W, y: H)])`; a thrown CI error → `EffectError.renderFailed`. (If the SDK refuses a non-property-list argument value, keep the pipelines in a lock-protected registry keyed by `device.registryID` filled by `CoreImageBridge` and pass only the name — record which variant was used in the Verification status.)
   - Overrides: `roi(forInput:arguments:outputRect:)` → `outputRect.insetBy(dx: −r, dy: −r)`; `formatForInput(at:)` → `.RGBA8`; `outputFormat` → `.RGBA8` (8-bit values are exact; the input is straight `.straight` bytes, the output is straight bytes).
   - `process(with:arguments:output:)`: requires `output.metalCommandBuffer` and the textures (missing → throw → `.renderFailed`). Allocates a private `MTLBuffer` scratch of `threads × 4 × 256 × UInt32` (4 KiB per thread) where `threads = outputHeight × ceil(outputWidth / segmentLength)`, capped at 64 MiB by dispatching **row batches** in separate compute encoders that reuse the buffer (hazard tracking serializes them). Passes `Unfocus.halfWidths(radius:)` (0064) converted to `[Int32]`, with `setBytes` (≤ 401 × 4 B), and a small parameter struct (mode, radius, percentile, strength, intensity, canvas W/H, the input/output region origins in canvas coordinates, the row-batch offset).
   - **Coordinates:** the compute function works in **canvas pixel coordinates** (y down). Output texel `(tx, ty)` ↔ CI pixel `(output.region.minX + tx, …)` ↔ canvas `(in.minX + ciX, in.maxY − 1 − ciY)`; the input texture is addressed the same way through `inputs[0].region`. The texture row order assumed is "row 0 = top of the region" — **verified by `LocalHistogramKernelTests.identityRoundTrip`**; if Core Image delivers bottom-up textures, flip the one `rowOf` helper in the shader (no other change).

4. **`PaintDotMac/Core/Rendering/Shaders/LocalHistogram.metal`** (new) — plain Metal compute function (not a CI kernel), `kernel void localHistogram(texture2d<float, access::read> src [[texture(0)]], texture2d<float, access::write> dst [[texture(1)]], device atomic_uint* /*or uint* */ scratch [[buffer(0)]], constant int* halfWidths [[buffer(1)]], constant LocalHistogramParams& p [[buffer(2)]], uint gid [[thread_position_in_grid]])`. **All math is integer except Reduce Noise's `lerp`.** One thread = one output row segment of `segmentLength` pixels; its four 256-bin `uint` histograms live in `scratch[gid · 1024 …]` (non-atomic; the thread owns them):
   - read helper `int4 px(int cx, int cy)` = `int4(rint(src.read(texel(cx, cy)) · 255))` (straight R, G, B, A).
   - **init** at the segment's first pixel `x0`: zero the 1,024 bins; for `v ∈ −r…r` with `0 ≤ y+v < H`, for `u ∈ −hw[v+r]…hw[v+r]` with `0 ≤ x0+u < W`: add the pixel to the four histograms, `area += 1`.
   - **per pixel** `x` of the segment (only `x < output maxX`): `dst.write(float4(apply(px(x, y), area, h)) / 255.0, …)`, then **slide** to `x+1`: for each row `v` in the canvas, remove `(x − hw, y+v)` if `x − hw ≥ 0` and add `(x + 1 + hw, y+v)` if `< W`, adjusting `area` (3.36's trailing/leading-edge update).
   - `apply` per mode — **literal transcriptions of the 3.36 loops on the histograms** (not the closed forms):
     - `identity`: the pixel itself.
     - `median`: `GetPercentile(p.percentile, area, …)` loops, per channel B, G, R, A.
     - `reduceNoise`: `rc`/`gc`/`bc` = prefix sums below the pixel's own channel value, `(c · 255) / area` (int), `I = (0.114·B + 0.587·G + 0.299·R) / 255.0` and `lerp = p.strength · (1 − 0.75·I)` in `float` (`precise::` not needed — no transcendental), `out = clampToByte(C + lerp·(n − C))` with `clampToByte(x) = x > 255 ? 255 : x < 0 ? 0 : int(x)` (truncation toward zero), alpha with `n = 255`.
     - `outline`: the six `while` loops of *Context* exactly, **including the `hb` skip loop for alpha**, `out = (255 − (c2 − c1)) per color, a2)`.
   - Overflow: `area ≤ 126,309`, `area · 200 ≤ 25.3 M`, `count · 255 ≤ 32.3 M` — all fit `int`.

## Open questions

Decided as stated (recommended answers applied in this spec); please confirm and record in PRD.md §5.9/§12:

1. **Median, Reduce Noise and Outline reproduce Paint.NET 3.36 bit-exactly, including the `GetPercentile` `+1` quirk shared with Sharpen (0042 *Open questions* 2): Median's "median" is one level above the true median (a flat 100 becomes 101, Percentile 100 gives max + 1), the disk is clipped at the canvas edge (not replicated), alpha is filtered like a color channel, and a fully transparent area becomes `(1,1,1,1)` under Median (so empty layers stop being sparse).** Consistent with 0042's choice and keeps GPU = oracle with zero differences. Alternative: true percentile (flat areas unchanged, transparent stays transparent) — then Sharpen should change too. Recommended: keep 3.36 exactly, same as Sharpen.
2. **Outline keeps 3.36's alpha computation, including its bug (the alpha skip loop reads the blue histogram, and the output alpha is the upper percentile `a2` itself):** on opaque images alpha stays 255, but semi-transparent areas can become opaque (flat `(0,0,200,100)` → alpha 255) or keep ~their alpha (flat `(200,0,0,100)` → 101), a 1×1 image gets alpha = its blue value, and transparent areas become `(255,255,255,1)`. Alternative: use the alpha histogram in the skip loop (fixes the blue dependency) or keep the source alpha. Recommended: keep 3.36 exactly (fidelity, zero-difference GPU), revisit if users hit it.
3. **Median stays in Effects ▸ Noise, named "Median", with Paint.NET 3.36's parameters (Radius 1–200 default 10, Percentile 0–100 default 50), as PRD §5.9 lists it.** Paint.NET 5 moved it to Effects ▸ Blurs as "Median Blur" and added a Quality option (EffectsNoiseMenu.html/EffectsBlursMenu.html). Recommended: follow the PRD (Noise ▸ Median); a later PRD change can move it without touching the algorithm.
4. **Relief uses 3.36's ColorDifference math (Double sums truncated toward zero, alpha 255) with clamped edge taps (0044 *Open questions* 2 applied) and runs on 0044's `edgeDetect` kernel in `float`, so it matches the Double oracle within ±1.** Consequence: in flat areas 3.36's Double rounding gives `v − 1` at several angles including the default 45° (40 → 39) while the GPU may give `v`; tests accept ±1 there. Alternative: snap sums within 1e-4 of an integer before truncating (flat areas always unchanged, GPU ≈ oracle exactly) — this would also need a separate kernel instead of reusing `edgeDetect`. Recommended: keep 3.36 math with ±1 (consistency with Edge Detect/Emboss).
5. **Paint.NET 5's *Quality* options (Outline, Median Blur) are not in v1.x**; parameter ranges/defaults come from the 3.36 source because the docs give none (only Percentile's default 50 is documented, and it matches). Recommended: omit Quality (can be added later as a schema parameter without breaking remembered values).
