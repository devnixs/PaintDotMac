### Paint.NET 3.36 behaviour (transcribed)

**Directional 3×3 weights** — identical code in `EmbossEffect.OnSetRenderInfo` and `EdgeDetectEffect.OnSetRenderInfo` (Double math): `r = angle · 2π / 360`, `dr = π / 4`; weights indexed `[fy][fx]`, `fy`/`fx` = 0…2 meaning source row `y − 1 + fy`, column `x − 1 + fx` (row 0 = above, y down):

```
w[0][0] = cos(r + dr)    w[0][1] = cos(r + 2dr)   w[0][2] = cos(r + 3dr)
w[1][0] = cos(r)         w[1][1] = 0              w[1][2] = cos(r + 4dr)
w[2][0] = cos(r − dr)    w[2][1] = cos(r − 2dr)   w[2][2] = cos(r − 3dr)
```
At angle 0 the left column is positive (0.7071, 1, 0.7071), the right column negative, the middle column 0 (≈ 6.1e−17); the weights sum to 0, so flat areas give 0.

**Emboss** (`EmbossEffect.OnRender`): `I(c) = c.GetIntensityByte() = (7471·B + 38470·G + 19595·R) >> 16` (alpha ignored); `sum = Σ w[fy][fx] · Double(I(src(x−1+fx, y−1+fy)))`; `iSum = Int(sum) + 128` where `Int()` truncates toward zero (C# `(int)`); clamp to 0…255; output `(iSum, iSum, iSum, 255)`. Defaults: `DoubleProperty(Angle, 0.0, −180.0, +180.0)`.

**Edge Detect** (`EdgeDetectEffect` → `ColorDifferenceEffect.RenderColorDifferenceEffect`): the same weights with per-channel sums `rSum = Σ w·R`, `gSum = Σ w·G`, `bSum = Σ w·B` (straight values, alpha ignored); each `Int()` truncated toward zero, clamped 0…255 (no +128 offset); output `(r, g, b, 255)`. Defaults: `DoubleProperty(Angle, 45.0, −180.0, +180.0)`. Flat areas therefore render black, matching the docs ("Non-edge areas render black").

**Edge pixels in 3.36:** at the canvas border the taps that fall outside are *skipped* (`fxStart/fxEnd/fyStart/fyEnd`), not clamped, which makes a flat image's border columns/rows black or white. This spec uses edge **clamping** instead (see *Open questions* 2).

**Pixelate** (`PixelateEffect`): `Int32Property(CellSize, 2, 1, 100)`, label "Cell size". The cell of pixel (x, y) is the `cellSize × cellSize` box with top-left `(x − x % cellSize, y − y % cellSize)` (grid anchored at the image origin (0,0)), intersected with the layer bounds, so cells on the right and bottom edges are partial. Every pixel of the cell gets the **same color: `BlendColors4W16IP` of the clipped cell's four corner pixels** (top-left, top-right, bottom-left, bottom-right; weights 16384 each) — Paint.NET 3.36 does *not* average every pixel of the cell (see *Open questions* 3). With equal weights `BlendColors4W16IP` reduces exactly to integer math:
```
ΣA = A_tl + A_tr + A_bl + A_br
a  = (ΣA + 2) >> 2                       // = (16384·ΣA + 32768) >> 16
if a == 0 → (0, 0, 0, 0)                 // also covers ΣA == 0 (no division)
else C = (Σ A_i · C_i) / ΣA  for C ∈ {R, G, B}   // integer division, floor (all terms ≥ 0)
```
(The 16384 factor cancels exactly in `(16384·n) / (16384·d) = n / d` for non-negative integers.) The cell is computed against the whole layer, not the selection: a cell crossing the selection edge uses unselected pixels, and only the selected part is written (FX-D mask blend).

## User story

As a PaintDotMac user, I choose Effects ▸ Stylize ▸ Emboss…, Effects ▸ Stylize ▸ Edge Detect…, or Effects ▸ Distort ▸ Pixelate…, adjust the Angle or Cell size in the generated dialog while the canvas previews the result, and either click OK (one history step named after the effect, undoable, repeatable with ⌘F) or Cancel (image unchanged). The effect only changes the active layer inside the selection.

## Edge cases

- **1×1 and 1×N images:** Emboss/Edge Detect: all taps clamp to the image itself → flat → Emboss (128,128,128,255), Edge Detect (0,0,0,255) (±1 per FP). Pixelate: the single cell's four corners are the same pixel(s) → for 1×1 the pixel itself when A > 0.
- **Cell size 1:** every pixel is its own cell; result = source for A ≥ 1, but (0,0,0,0) where A == 0 (color under transparent pixels is cleared — Paint.NET's `a == 0` branch). Not a no-op: the step is recorded if any byte changes (H-6 no-op rule from 0008 otherwise).
- **Cell size larger than the image** (e.g. 100 on 30×20): one partial cell = whole image, corners (0,0), (29,0), (0,19), (29,19).
- **Cell boundaries across tiles/chunks:** cell size 100 with chunks of 512 px → cells at x = 500…599 span two chunks; `inputPadding = 99` guarantees each chunk reads all four corners; result identical to a single-chunk render.
- **Transparent and semi-transparent pixels:** Emboss/Edge Detect ignore alpha and output alpha 255 (a fully transparent layer becomes opaque: Emboss gray 128, Edge Detect black; all tiles allocated). Pixelate weights color by alpha and averages alpha with `(ΣA + 2) >> 2`.
- **Empty (unallocated) tiles:** read as (0,0,0,0) → Emboss 128 gray opaque, Edge Detect black opaque (tiles allocated); Pixelate keeps them all-zero (stay sparse via `EffectMaskBlend.blendTile`'s all-zero → nil rule).
- **Angle ±180 and 0 vs 360-equivalents:** −180 and 180 give the same weights up to Double rounding (≤ 1e−15; cos is 2π-periodic) → the same output (±1 on the GPU). Angle values are normalized to 2 decimals by 0031.
- **Hidden active layer, selection, floating pixels, busy document, no GPU:** handled by 0031 (effect runs on the hidden layer; "Finish Pixels" first; menu items disabled while busy or without a bridge).
- **Largest images:** 65,535×1 Pixelate cell 100 and Emboss: no overflow (all per-pixel integer math ≤ 260,100; tiles via the runner).
- **Cancel mid-render / close window mid-render:** 0031 session semantics (exact restore, no step, no crash).

## Open questions

Decided as stated (recommended answers applied in this spec); please confirm and record in PRD.md §5.9/§12:

1. **Emboss and Edge Detect output opaque pixels (alpha 255) and ignore the source alpha**, exactly like Paint.NET 3.36 (`FromBgra(…, 255)`), so applying them to a layer with transparent areas makes the whole layer (or the selected part) opaque — Emboss gray, Edge Detect black where flat. Alternative: keep each pixel's source alpha. Recommended: keep Paint.NET's behaviour (alpha 255).
2. **Canvas-border pixels of Emboss and Edge Detect use clamped (edge-replicated) neighbours** (0031's `clampedToExtent`), instead of Paint.NET 3.36's skipped taps, which turn a flat image's outermost columns and rows black or white (e.g. Emboss at angle 0 makes the left column black and the right column white). Recommended: clamp (no border artefact; consistent with every other neighbourhood effect).
3. **Pixelate uses Paint.NET 3.36's algorithm: each cell gets the alpha-weighted blend of its four corner pixels (not the mean of all cell pixels), cells anchored at the image's top-left, partial cells at the right/bottom edges, Cell size 1–100 default 2.** Paint.NET 5's extra "Scale Down"/"Scale Up" algorithm choices are not implemented (their option names and defaults are undocumented). Alternative: true cell average. Recommended: Paint.NET 3.36 corner blend, no Scale Down/Up options in v1.0.
4. **Edge Detect is Paint.NET 3.36's angle-based Edge Detect (one "Angle" parameter, −180…180, default 45), not Paint.NET 5's redesigned Edge Detect** (Strength, Blurring, Algorithm Prewitt/Sobel (default Sobel), Overlay Edges — EffectsStylizeMenu.html documents these names but no ranges or defaults, so it cannot be specified from the docs per FX-E). Recommended: 3.36 angle version for v1.0.
5. **Angle range is −180…180° for both** (Paint.NET 3.36 `DoubleProperty(Angle, default, −180, +180)`, 0031's `.angle` default range), shown with 2 decimals; the docs give no range. Alternative: 0…360. Recommended: −180…180.
