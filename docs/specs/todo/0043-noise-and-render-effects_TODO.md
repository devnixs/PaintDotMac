**Paint.NET 3.36 behavior mirrored (transcribed from the source above).**

*Add Noise* (`AddNoiseEffect`, submenu Noise): `Int32Property(Intensity, 64, 0, 100)`, `Int32Property(Saturation, 100, 0, 400)` (label "Color Saturation"), `DoubleProperty(Coverage, 100, 0, 100)` (label "Coverage", exponential slider). Per pixel: with probability `coverage/100` the pixel gets noise, otherwise it is copied. Noise = three draws from a 16,384-entry Gaussian lookup table, desaturated toward their intensity by `sat`, scaled by `dev`, added to R, G, B and clamped; **alpha is copied**. 3.36 draws from an unseeded `[ThreadStatic] System.Random`, so its output depends on thread scheduling and tile order — **not reproducible**. Paint.NET 5 adds "Randomize" (docs). This spec keeps 3.36's math exactly and replaces the RNG by a **counter-based per-pixel hash** of `(seed, x, y)` (*Scope* item 2), which makes the result a pure function of seed + canvas coordinate.

*Clouds* (`CloudsEffect`, submenu Render): `Int32Property(Scale, 250, 2, 1000)` (label "Scale"), `DoubleProperty(Power, 0.5, 0.0, 1.0)` (label **"Roughness"**, up/down increment 0.01), `StaticListChoiceProperty(BlendOp, UserBlendOps.GetBlendOps(), 0)` (label "Blend Mode", default index 0 = Normal), `Int32Property(Seed, 0, 0, 255)` shown as an increment button "Reseed" under the header "Random Noise". Colors: `EnvironmentParameters.PrimaryColor` → `SecondaryColor`. Rendering is 2-D Ken Perlin improved noise (permutation table and `Fade`/`Grad`/`Lerp` transcribed in *Scope* item 6), up to 12 octaves, centred on the canvas (`dx = 2x − w`, `dy = 2y − h`), so every pixel is a pure function of `(x, y, canvas size, parameters)`. The cloud pixel then goes through the chosen `UserBlendOp` with the **layer pixel as the bottom (lhs) and the cloud as the top (rhs)**. 3.36 XORs the seed with a per-instance `instanceSeed` "so that repetition of the effect with CTRL+F actually shows up differently" (see *Open questions* 1).

## User story

As a Paint.NET switcher, I choose **Effects ▸ Noise ▸ Add Noise…**, see grain appear live on the active layer (only inside my selection, with soft edges), tune Intensity, Color Saturation and Coverage, press **Reseed** for a different grain, and OK records one "Add Noise" step. I choose **Effects ▸ Render ▸ Clouds…**, get clouds from my primary to my secondary color, change Scale, Roughness, Blend Mode (any layer blend mode, e.g. Multiply over a photo), Color 1/Color 2, or Reseed, and OK records one "Clouds" step. The same seed always gives the same pixels, however the image is tiled or which part renders first; ⌘F repeats the effect with the same settings and a fresh seed, like Paint.NET.

1. **`PaintDotMac/Core/Effects/EffectSeedSource.swift`** (new) — the one source of fresh seeds for dialogs, Reseed and Repeat.
   ```swift
   public struct EffectSeedSource: Sendable {
       public static func system() -> EffectSeedSource                 // SystemRandomNumberGenerator
       public static func deterministic(start: UInt64) -> EffectSeedSource   // SplitMix64, for tests and -UITestEffectSeed
       public mutating func next() -> UInt64
   }
   ```
   SplitMix64 (exact): `state &+= 0x9E3779B97F4A7C15; z = state; z = (z ^ (z >> 30)) &* 0xBF58476D1CE4E5B9; z = (z ^ (z >> 27)) &* 0x94D049BB133111EB; return z ^ (z >> 31)`. Known values: start 0 → first `0xE220A8397B1DCDAF`; start 42 → `0xBDD732262FEB6E95`, `0x28EFE333B266F103`, `0x47526757130F9F52`.
   **Consumption order (normative, UI tests rely on it):** `runEffect` calls `next()` exactly once per dialog/no-dialog run (the value passed as `seed:` to `initialValues`, used only when nothing is remembered); each **Reseed** click calls `next()` once; each Repeat calls `next()` once per `.seed` parameter in schema order (item 3). Nothing else calls it.

2. **`PaintDotMac/Core/Effects/PixelHash.swift`** (new) — counter-based per-pixel randomness (the scheme that makes random effects independent of tiling and render order). All arithmetic is `UInt32` with wrapping `&*`/`&+`; shared bit-for-bit by Swift and Metal.
   ```swift
   public enum PixelHash {
       public static func mix(_ v: UInt32) -> UInt32          // v ^= v >> 16; v &*= 0x7FEB352D; v ^= v >> 15; v &*= 0x846CA68B; v ^= v >> 16
       public static func runKey(seed: UInt64) -> UInt32      // mix(UInt32(truncatingIfNeeded: seed) ^ mix(UInt32(truncatingIfNeeded: seed >> 32)))
       public static func pixelKey(runKey k: UInt32, x: Int, y: Int) -> UInt32   // mix(mix(k ^ UInt32(x)) ^ (UInt32(y) &* 0x9E3779B9))
       public static func draw(_ pixelKey: UInt32, _ n: UInt32) -> UInt32        // mix(pixelKey &+ n &* 0x68E31DA4)
   }
   ```
   `x`, `y` are **canvas** pixel coordinates (0…65,534), never region-relative. Known values (computed with a standalone Python transcription, independent of the app): `mix(0) = 0`, `mix(1) = 0x688990C0`, `runKey(0) = 0`, `runKey(1) = 0x688990C0`, `runKey(0x0123456789ABCDEF) = 0x5CBD2392`; with that run key: `pixelKey(0,0) = 0x0B5CEA83` and draws n=0…3 `0xFCD453D8, 0xABE3ACF2, 0xA814083B, 0xA182A91E`; `pixelKey(1,0) = 0x9FC0903D` (draws `0xE7BE3F57, 0x695C53D5, 0x381583D4, 0x3A03917F`); `pixelKey(0,1) = 0xBDDF1B77`; `pixelKey(256,0) = 0xAFDD45E7`; `pixelKey(65534,65534) = 0x07653E85`.

4. **Gaussian lookup table** — `static` members of `AddNoise` (item 5, same file `PaintDotMac/Core/Effects/Effects/Noise/AddNoise.swift`, 0041's "pure helpers as `static` members" rule): `public static let tableSize = 16384`, `public static let lookup: [Int32]`, `public static func lookupImage() -> CIImage`.
   - `lookup` = literal transcription of 3.36 `InitLookup` in `Double` (`NormalCurve(x, scale) = scale · exp(−x·x/2)`; bisection `l = 5, r = 10` while `r − l > 0.0000001` with `scale = (l + r)·0.5`, inner sum over `i` in 0..<16384 of `NormalCurve(16.0·(Double(i) − 8192)/16384, scale)` breaking when `sum > 1_000_000`, `sum > 16384 → r = scale`, `< → l = scale`, `== → break`; then the fill loop `roundedSum = Int(sum)` (truncation), `lookup[j] = (i − 8192)·65536/16384` for `j` in `lastRoundedSum..<roundedSum`, untouched entries 0). Computed once (`static let`).
   - Known values (Python transcription on macOS libm): bisection ends with `scale = 6.383076533675194` after 26 iterations; final `roundedSum = 16384` (no untouched tail); `lookup[0] = −15736`, `[1] = −15024`, `[100] = −10252`, `[1000] = −6332`, `[4096] = −2760`, `[8191] = 0`, `[8192] = 0`, `[12288] = 2764`, `[16000] = 8144`, `[16382] = 15736`, `[16383] = 23200`; min −15736, max 23200, exactly 7 entries are 0, sum of all entries = 23192. Every entry is a multiple of 4.
   - `lookupImage()` (cached) — the table as a 128×128 straight **RGBA8** `CIImage` built like 0031's `makeInputImage` (`colorSpace: nil`, no premultiply): entry `j` stored in buffer row `j >> 7`, column `j & 127` as `v = lookup[j]/4 + 8192` (range 4258…13992, 14 bits): `R = v & 255`, `G = v >> 8`, `B = 0`, `A = 255`. In CI space (first buffer row at the top) entry `j` sits at pixel `(j & 127, 127 − (j >> 7))`. Sampled with `.samplingNearest()`.

5. **`PaintDotMac/Core/Effects/Effects/Noise/AddNoise.swift`** (new) — `public struct AddNoise: ImageEffect`: `id "addNoise"`, `name "Add Noise"`, `category .noise`, no shortcut, `.straight`, `inputPadding` 0, parameters in this order:
   | id | label | kind |
   |---|---|---|
   | `intensity` | "Intensity" | `.integer(range: 0...100, defaultValue: 64)` |
   | `colorSaturation` | "Color Saturation" | `.integer(range: 0...400, defaultValue: 100)` |
   | `coverage` | "Coverage" | `.double(range: 0...100, defaultValue: 100, step: 0.01, decimals: 2)` |
   | `seed` | "Randomize" | `.seed` (button "Reseed") |
   Pure helpers (unit-tested): `static func dev(intensity:) -> Int32` = `intensity·intensity/4` (integer division); `static func sat(colorSaturation:) -> Int32` = `colorSaturation·4096/100`; `static func coverageThreshold(_ coverage: Double) -> UInt32` = `UInt32((coverage/100 · 16_777_216).rounded(.toNearestOrAwayFromZero))` (100 → 16,777,216, 50 → 8,388,608, 0.01 → 1,678, 0 → 0).
   **Per-pixel algorithm (normative; CPU oracle and GPU kernel both implement exactly this; all `Int32`, `>>` arithmetic):**
   ```
   k = PixelHash.runKey(seed);  p = PixelHash.pixelKey(k, x, y)          // canvas x, y
   if (draw(p,0) >> 8) >= threshold { out = src }                         // 24-bit uniform; replaces `NextDouble() > coverage`
   else {
     r = lookup[draw(p,1) >> 18]; g = lookup[draw(p,2) >> 18]; b = lookup[draw(p,3) >> 18]   // 14-bit index; replaces Next(16384)
     i = (4899·r + 9618·g + 1867·b) >> 14
     r = i + (((r − i)·sat) >> 12);  g = i + (((g − i)·sat) >> 12);  b = i + (((b − i)·sat) >> 12)
     out = (clamp(R + ((r·dev + 32768) >> 16)), clamp(G + ((g·dev + 32768) >> 16)), clamp(B + ((b·dev + 32768) >> 16)), A)   // clamp = ClampToByte(int)
   }
   ```
   No intermediate overflows `Int32` (max |(r − i)·sat| < 2³¹, max |r·dev| ≈ 6.6·10⁸). Intensity 0 (`dev = 0`) and Coverage 0 (`threshold = 0`) change nothing → no-op, no history step (H-6). Color under alpha 0 is noised too (0031 open question 4, Paint.NET per-pixel behavior), so a transparent tile can become allocated.
   `makeOutput`: general kernel `context.kernel("addNoise")` applied with extent = `context.ciRect(context.outputRect)`, ROI callback: argument 0 → the destination rect, argument 1 → the table extent `(0,0,128,128)`; arguments `[input, AddNoise.lookupImage().samplingNearest(), kLo, kHi, threshold, dev, sat, originX, originTop]` where `kLo = Float(k & 0xFFFF)`, `kHi = Float(k >> 16)` (CI kernel arguments are floats; 16-bit halves and every other value ≤ 2²⁴ are exact), `threshold` as `Float` (≤ 2²⁴, exact), `originX = Float(inputRect.minX)`, `originTop = Float(inputRect.maxY)`.

   The blend list therefore always equals the implemented layer blend modes (D-15; 0059 appends L-4 modes automatically on the Swift side — see *Out of scope*). Effective Perlin seed = `UInt8(truncatingIfNeeded: seed)` (3.36's seed is a byte; *Open questions* 3).
   Pure helpers (unit-tested): `static func octaveCount(scale: Int, roughness: Double) -> Int` = literal 3.36 loop in `Double` (`mult = 1, div = scale, i = 0; while i < 12 && mult > 0.03 && div > 0 { div /= 2; mult *= roughness; i += 1 }`), computed on the CPU so the GPU never makes the `mult > 0.03` decision in `Float`; `static func blendIndex(_ mode: BlendMode) -> Int` = `BlendMode.allCases.firstIndex(of:)`. Known: (250, 0.5) → 6, (2, 0.5) → 2, (1000, 0.5) → 6, (250, 0) → 1, (250, 1) → 8, (3, 1) → 2, (1000, 1) → 10, (250, 0.25) → 3, (250, 0.03) → 1.
   **Per-pixel algorithm (Paint.NET 3.36 `RenderClouds` + `Noise`, normative):** with canvas `w, h`, canvas `x, y`:
   ```
   P = Ken Perlin's permutation [151,160,137,91,90,15,131,13,201,95,96,53,194,233,7,225,140,36,103,30,69,142,8,99,37,240,21,10,23,190,6,148,247,120,234,75,0,26,197,62,94,252,219,203,117,35,11,32,57,177,33,88,237,149,56,87,174,20,125,136,171,168,68,175,74,165,71,134,139,48,27,166,77,146,158,231,83,111,229,122,60,211,133,230,220,105,92,41,55,46,245,40,244,102,143,54,65,25,63,161,1,216,80,73,209,76,132,187,208,89,18,169,200,196,135,130,116,188,159,86,164,100,109,198,173,186,3,64,52,217,226,250,124,123,5,202,38,147,118,126,255,82,85,212,207,206,59,227,47,16,58,17,182,189,28,42,223,183,170,213,119,248,152,2,44,154,163,70,221,153,101,155,167,43,172,9,129,22,39,253,19,98,108,110,79,113,224,232,178,185,112,104,218,246,97,228,251,34,242,193,238,210,144,12,191,179,162,241,81,51,145,235,249,14,239,107,49,192,214,31,181,199,106,157,184,84,204,176,115,121,50,45,127,4,150,254,138,236,205,93,222,114,67,29,24,72,243,141,128,195,78,66,215,61,156,180]
   L[i] = P[i & 255]   (3.36's 512-entry permuteLookup = P twice)
   Fade(t) = t·t·t·(t·(t·6 − 15) + 10)
   Grad(hash, x, y): h = hash & 15; u = h < 8 ? x : y; v = h < 4 ? y : (h == 12 || h == 14 ? x : 0); return ((h & 1) == 0 ? u : −u) + ((h & 2) == 0 ? v : −v)
   Lerp(a, b, t) = a + t·(b − a)
   Noise(ix, iy, fx, fy, s):  u = Fade(fx); v = Fade(fy)
       a = L[ix + s] + iy; aa = L[a]; ab = L[a + 1]; b = L[ix + 1 + s] + iy; ba = L[b]; bb = L[b + 1]
       return Lerp(Lerp(Grad(L[aa], fx, fy), Grad(L[ba], fx − 1, fy), u), Lerp(Grad(L[ab], fx, fy − 1), Grad(L[bb], fx − 1, fy − 1), u), v)
   dx = 2x − w; dy = 2y − h; val = 0; mult = 1; div = scale
   for i in 0..<octaveCount:
       dxr = 65536 + dx/div; dyr = 65536 + dy/div        (real division)
       dxd = trunc(dxr); dyd = trunc(dyr); fx = dxr − dxd; fy = dyr − dyd
       val += Noise(dxd & 255, dyd & 255, fx, fy, (seedByte ^ i) & 255) · mult
       div = div / 2 (integer); mult *= roughness
   f = (val + 1)/2
   cloud = (c(C1.r, C2.r), c(C1.g, C2.g), c(C1.b, C2.b), c(C1.a, C2.a)) with c(p, q) = ClampToByte(p + f·(q − p))   // ClampToByte(double): >255 → 255, <0 → 0, else truncate
   out = BlendOps.blend(blendMode, dst: layerPixel, src: cloud)     // layer = bottom (3.36 lhs = SrcArgs), cloud = top (rhs), opacity 255
   ```
   (3.36 skips the blend for Normal with two opaque colors as an optimization; Normal with an opaque top returns the top exactly, so always blending is identical.) Normal with both colors' alpha 0 changes nothing (BlendOps' `Sa == 0` early return) → no step.
   **GPU formulation (precision):** `Float` cannot hold `65536 + dx/div` precisely (8 fraction bits), so the kernel uses the exact integer decomposition, mathematically identical to 3.36's: `div_i = scale >> i` (integers), `q = floorDiv(dx, div_i)` (MSL `/` truncates; subtract 1 when `dx < 0` and `dx % div_i != 0`), `ix = q & 255` (equals `(65536 + q) & 255`), `fx = Float(dx − q·div_i) / Float(div_i)`; same for y. The rest runs in `Float`; this is the only source of GPU/CPU difference (truncation boundaries → ±1 on the cloud pixel).
   `makeOutput`: color kernel `context.colorKernel("clouds")` with a trailing `coreimage::destination` (fallback if CI rejects `destination` in a color kernel: a general `CIKernel` with ROI = destination rect, same arguments), arguments `[input, Float(w), Float(h), Float(scale), Float(octaveCount), Float(roughness), Float(seedByte), CIVector(c1 bytes), CIVector(c2 bytes), Float(blendIndex), originX, originTop]` (color components passed as byte values 0…255).

## Edge cases

- **Coverage 0 / Intensity 0:** output == input, no step. **Coverage 0.01:** threshold 1,678 → ~0.01% of pixels change. → `AddNoiseTests.helpers`, `NoiseEffectsIntegrationTests.noOpSettingsAddNoStep`, `NoiseEffectsUITests.testAddNoiseCoverageZeroIsNoOp`
- **Color Saturation 0:** r = g = b (gray noise); 400: strongly colored, clamped. → `AddNoiseReferenceTests.handVectors`
- **Transparent pixels:** Add Noise keeps alpha, noises the color under alpha 0 (e.g. (0,0,0,0) → (28,26,21,0) at (0,0) for the test seed), allocating unallocated tiles; Clouds Normal with opaque colors fills transparent tiles completely. → `NoiseGoldenTests.sparseTiles`, `RenderGoldenTests.sparseTiles`
- **Clouds colors with alpha 0** (both): Normal → no change, no step; one: shades between the other color and transparent (docs). → `CloudsReferenceTests.transparentColors`, `RenderEffectsIntegrationTests.noOpSettingsAddNoStep`
- **Canvas centre** `(w/2, h/2)` with even w, h: `val = 0` exactly → `f = 0.5` → black→white gives 127 for any seed/scale. → `CloudsReferenceTests.centreIsMidpoint`
- **Scale 2, Roughness 1** (2 octaves), **Scale 1000, Roughness 1** (10 octaves), **Roughness 0** (1 octave), **Roughness 0.03** (1 octave: `0.03 > 0.03` is false). → `CloudsTests.octaveCount`
- **Negative `dx`/`dy`** (left/top half): floor division and `& 255` wrap correct on GPU. → `RenderGoldenTests.normalGrid` (fixture covers both halves), `CloudsReferenceTests.floorDecomposition`
- **Large/odd canvases:** 1×1, 257×257, 65,535×1 (x up to 65,534; `dx` up to 65,534) — no overflow, correct last row/column, out-of-canvas bytes 0. → `NoiseGoldenTests.edgeTiles`, `.extremeAspect`, `RenderGoldenTests.edgeTiles`, `.extremeAspect`
- **Seed 0** (run key 0) still produces noise (no degenerate all-zero hash). → `PixelHashTests.seedZeroNotDegenerate`
- **Hidden active layer, floating pixels, busy document, Cancel mid-render, GPU failure:** handled by 0031's framework unchanged; covered by 0031's tests plus `NoiseEffectsIntegrationTests.cancelRestoresExactly`, `RenderEffectsIntegrationTests.cancelRestoresExactly`.
- **Blend mode list growth:** a `BlendMode` case without a `blend_mode_at` entry falls back to Normal on GPU and fails `RenderGoldenTests.blendStage(mode:)` — never a crash.

## Open questions

Decided as stated (recommended answers applied in this spec); please confirm and record in PRD.md §5.9/§12:

1. **⌘F Repeat on a seeded effect uses a fresh seed (the other values stay the same); the dialog still reopens with the last OK'd seed.** Verified in Paint.NET 3.36: Add Noise draws from an unseeded RNG and `CloudsEffect` XORs a per-instance seed "so that repetition of the effect with CTRL+F actually shows up differently" — so Paint.NET does *not* reuse the same randomness on Repeat (the assignment's assumption was the opposite). This changes 0031's note "A `.seed` value is remembered like any other value (Repeat is deterministic)" for Repeat only; each run is still deterministic for its seed (FX-B), and the history step stores the pixels. Recommended: yes (Paint.NET behavior; repeating Add Noise with the same seed would only re-amplify the identical grain). Alternative: reuse the remembered seed exactly (0031 as written).
2. **Labels follow the Paint.NET 5 docs where 3.36 differs:** the seed row is labelled "Randomize" (docs) with 0031's generic button text "Reseed" (3.36's button text; 3.36's header was "Random Noise"); Clouds' second parameter is "Roughness" (3.36 internal name "Power"); Clouds has "Color 1"/"Color 2" color parameters defaulting to the primary/secondary colors (Paint.NET 5 Colors tab; in 3.36 the colors were not editable in the dialog), shown in one list after the Configuration parameters because the generated dialog has no tabs. Recommended: yes.
3. **Clouds' Perlin seed is the low 8 bits of the 64-bit seed**, so there are 256 distinct cloud patterns per (scale, roughness, size), exactly as in 3.36 (`Int32Property(Seed, 0, 0, 255)`, used as a byte). Recommended: keep 3.36's byte seed (fidelity, no table changes). Alternative: derive a per-seed permutation for more variety (diverges from Paint.NET).
4. **Ranges and defaults come from the 3.36 source** (Add Noise Intensity 0–100/64, Color Saturation 0–400/100, Coverage 0–100/100 with 2 decimals; Clouds Scale 2–1000/250, Roughness 0–1/0.50, Blend Mode Normal) because the docs give none; they are assumed equal to Paint.NET 5's dialog defaults (FX-E), which could not be checked without running Paint.NET 5. Coverage's exponential slider scale is not reproduced (0031's sliders are linear). Recommended: accept.
5. **Add Noise's random draws use the counter hash of *Scope* item 2 instead of Paint.NET's `System.Random`**, so the noise statistics (Gaussian table, coverage probability, saturation) match Paint.NET but no image will be pixel-identical to a Paint.NET run (Paint.NET's own output is not reproducible either). Recommended: yes (required for FX-B determinism and tile-order independence).
